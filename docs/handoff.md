- Boss 蓄力、護盾、圖騰已有進度與「還差多少」提示。
- 旗標已改成明確名稱與效果；軍旗有狀態、倒數與對應演出。
- 技能支援長按查看完整說明；未解鎖技能不再提前占用操作列。
- SpotlightTeach 已涵蓋 boss30、護盾、蓄力、圖騰、完美引爆五個首次教學時刻。

#### 2. 裝備穿上後仍然要能操作

**原始回饋**

- 裝備一旦穿上,就無法直接處理；必須先脫下來才能做其他操作,不符合直覺。

**目前結果**

- 已穿裝備可直接展開詳情。
- 可在裝備卡直接卸下、銘刻、餵武器或分解,不必先回背包繞一圈。
- 卡片只保留一個主要動作,其他操作收進「更多」；分解用危險操作樣式。
- 原生 `confirm()` 已改成遊戲內確認視窗。

#### 3. 第一技能不能是第二技能唯一的存在理由

**原始回饋**

- 「第一個技能累積、第二個技能引爆」太綁定。
- 沒有第一技能時,第二技能幾乎沒有價值,玩家會覺得拿到一個殘缺技能。

**目前結果**

- 第二技能在零印記時也能使用,不再完全被第一技能鎖住。
- 每 10 次擊殺會自然取得 1 印記,讓自動戰鬥與其他技能組合也能推進引爆。
- 滿印記後開啟 4 秒完美窗口；手動抓時機會得到士氣、傭兵推進與昂揚,自動引爆仍可正常運作但沒有完美獎勵。
- 後續做技能或職業時,禁止再設計「沒有 A,B 就等於廢招」的硬依附；連動應該是加深玩法,不是補齊基本功能。

#### 4. 傷害顯示不能一直是 1,也不要靠小數表達成長

**原始回饋**

- 點擊時傷害一直顯示 1,不知道實際有沒有成長。
- 整體數字出現小數看起來不爽；與其顯示零碎小數,應該整體同比放大並使用整數。

**決策與目前結果**

- 戰鬥 HP 與傷害同比放大 100 倍,經濟數值不動,避免破壞金幣曲線。
- 舊存檔已有換尺遷移。
- 戰鬥數字統一使用無小數整數格式。
- 點擊跳字顯示實際造成的傷害與取得的戰意,不再永遠只看到固定的 1。
- 若分帳或暴擊把正傷害拆成 `(0,1)`,顯示最低為 1,但核心仍保留正確精度。
- 未來不能只為「數字變大」單獨放大玩家傷害；敵人 HP 必須同比,維持實際擊殺時間。

#### 5. 介面的理想方向

**使用者提供的參考圖重點**

- 手機直式介面,戰場始終保留在上方,下方才是可捲動功能面板。
- 深紫色幻想風、卡片分層、細描邊與局部發光,不要像工程表單。
- 頁首置中且層級單純；底部固定六分頁,目前分頁用紫色發光清楚標示。
- 英雄頁應一眼看到角色/武器主卡、等級進度、DPS/暴擊/金幣三項核心數據、升級選項與下一階段。
- 裝備、職業、命運與傭兵都以可掃讀卡片呈現；鎖定內容要說明解鎖條件,不能只顯示 `???`。

**目前已落地**

- 統一置中頁首、漸層卡片、細框與發光底部導航。
- 手機面板固定保留約 25% 戰場,內容可捲動且不被導航、安全區遮住。
- 英雄頁改為武器/職業主卡、三欄戰鬥數據、勳章卡與升級列。
- 裝備五槽卡片化；命運三路加入圖示與明確選擇卡。
- 戰場狀態改為「一張主要機制卡 + 次要狀態 chips」,避免訊息同時堆滿。
- 技能列上方有下一步提示條,點擊可直接前往對應分頁。

**仍要遵守**

- 不要為了塞更多資訊壓縮戰場到看不見角色。
- 不要讓鎖定卡、長文與次要按鈕搶走主操作。
- 新面板要先以手機尺寸驗收,再看桌面；不能只靠桌面畫面判斷專業度。
- 完整演出規格與已完成狀態見 `docs/視覺效果缺口_給Codex.md`,不要只讀本節摘要。

#### 6. 「專業」不是裝飾更多,而是因果更清楚

使用者要求重新檢視專業程度後,採用的判準如下:

- 玩家看到結果時,能立刻知道是哪個操作或機制造成。
- 一個畫面只強調當下最重要的決策,其他資訊退到次層。
- 動畫有功能:預告、命中、結果、殘留；不能只是同時發光。
- 名稱、圖示、數字與演出要說同一件事。
- 所有隨機結果要先算好,演出只負責揭曉,不可暗中改機率。
- 「程式做到了」不等於「玩家感受到了」；實機可讀性是完成條件。

#### 7. Game Review 是長期工作方式,不是一次性的展示頁

**使用者認可的格式**

每張設計卡固定包含:

- Priority:`P0`~`P3`
- Problem:玩家實際遇到什麼問題
- Why:造成問題的系統原因
- Solution:具體修改方案
- Expected Result:改完後玩家會感受到什麼
- Files:預計影響的檔案

每張卡應能展開、留言、完成、延後及指派工程師。首頁可以快速掃描所有標題與優先級。
先前舉例的 `Game Review +127 -3` 是 Code Review 式資訊密度的概念示意,不是目前真實統計。

**核心目的**

- 專案不缺另一份 100 頁 GDD,缺的是可以執行、驗收與關閉的設計任務。
- 每張卡都必須讓工程師知道「為什麼改、要改什麼、玩家最後得到什麼」。
- 設計文件仍保留世界觀與全局規則；Game Review 負責追蹤當下體驗缺口,兩者不能互相取代。
- 完成程式後先進 `review` 待驗收,不要自行把設計卡標成 `done`。

#### 9. 設計概念與決策原因

##### 遊戲整體要回答的問題

這款遊戲不是單純把 DPS 數字往上堆。理想循環是:

`看見問題 → 做出選擇 → 戰場立即回應 → Build 逐步成形 → 下一個問題迫使玩家再調整`

因此每個系統至少要負責一件事:

- 提出一個玩家看得懂的問題。
- 給玩家兩個以上有取捨的答案。
- 讓選擇結果能在操作、出手順序或戰場畫面上被感受到。

如果一個系統只有百分比、沒有選擇；或核心有運算、畫面沒有因果,都還不算完成。

##### 為什麼命運不能只是公開技能樹

原本的命運樹會提前公開所有路徑。玩家第一次看似有選擇,但攻略一旦形成,
之後每輪只是照固定答案點完；它比較像技能樹,不像一次冒險中突然發生的命運。

所以目前採用:

`10F 命運降臨(不可預知的條件) → 20Lv 職業詮釋(用自己的方式承接) → 30F 命運抉擇(玩家三選一) → 流派開始成形`

- 10F 隨機是為了創造期待感與每輪差異。
- 20Lv 職業詮釋是為了讓同一事件在不同角色手上產生不同玩法。
- 30F 三選一是把構築主導權還給玩家,避免整輪都被隨機結果支配。
- 因此「整棵命運樹全部隨機」已否決；那會讓玩家失去規劃,也會破壞共鳴系統的前提。
- 命運卡先說方向與代價、不公開完整攻略,是為了保留發現感,不是故意隱藏規則。

##### 為什麼金幣不能只有升級

金幣若只能買共用等級,玩家面對的不是投資決策,只是「亮了就按」。
數字雖然持續上升,Build 卻沒有因為玩家花錢方式而不同。

首輪先保留原本共用等級,再於 Lv.10/20/30/40/50 加入訓練方向,原因是:

- 不直接拆掉已驗證的經濟與成長曲線。
- 讓同樣 Lv.40 的角色因投資選擇而有不同節奏。
- 用里程碑週期性打斷無腦升級,但不把主畫面變成複雜商店。
- 重擊與疾攻維持相同平均 DPS,差別放在單擊感、觸發頻率與技能配合,
  才是真正的玩法取捨,不是一個選項偷偷比較強。
- 戰意方向則服務主動點擊玩家,讓「我有操作」和「我完全放置」出現不同循環。

目前只是第一輪改善。若仍覺得金幣缺乏投資感,應新增第二個常態用途,
而不是繼續堆更多線性百分比。

##### 為什麼職業不能直接鎖死流派

若 20Lv 一選職業就決定唯一玩法,後面的命運、裝備與傭兵只剩把同一條線加深。
玩家不是在組 Build,而是在選預製角色。

職業應該是「如何解讀已遇到的命運」:

- 同一顆命運種子交給不同職業,要改變操作方式、技能順序或戰場位置。
- 同一職業在 30F 仍要保留至少兩個成立方向,不能只有唯一正解。
- 差異優先做成機制,例如承傷後回放、施法後餘響、繞背製造破綻；
  不要只換名稱或加不同顏色的傷害百分比。

這也是下一張 P1 要先補重裝步兵與隨軍法警詮釋的原因。

##### 為什麼技能連動不能互相綁架

好連動應該讓兩個完整技能組合後產生更高上限；壞連動則是 A 不存在時,B 連基本價值都沒有。
後者會造成假選擇,因為玩家看似有兩個技能,實際上只拿到一組不可拆的套件。

因此第二技能必須能獨立使用,印記也要有第一技能以外的來源。
第一技能帶來的價值應是更快、更準或更有策略地引爆,不是替第二技能補上最基本功能。

##### 為什麼傭兵要成為 Build 核心

如果傭兵只是背景自動攻擊與額外 DPS,玩家不需要圍繞他們做任何決定,
五名傭兵即使有不同動畫,玩法上仍只是同一條傷害來源。

後續 P1 的方向應是讓傭兵改變:

- 技能或普攻的觸發順序。
- 玩家能處理哪一種敵人問題。
- Build 的空窗、資源取得或爆發時機。

傭兵仍不能變成另一排線性升級；重點是「帶誰會改變打法」,不是「誰的百分比較高」。

##### 為什麼敵人必須提出問題

只增加 HP 的敵人只會問「你的 DPS 夠不夠」,最後所有 Build 都用同一把尺比較。
敵人的職責是迫使玩家檢查自己的構築:

- 護盾問玩家是否有破盾與來源分配。
- 蓄力問玩家能否保留技能並在正確窗口打斷。
- 圖騰問玩家是否有穿透、轉火或快速處理附屬目標的方法。

一般敵人也應逐步帶入輕量版問題,讓玩家在 Boss 前學會應對。
不能只換名字、顏色與體型後宣稱有新敵人玩法；目前敵種系統主要解決內容辨識,
P1 Review 才負責補戰鬥問題。

##### 為什麼 Boss 不能只是血量更厚

Boss 若只是高 HP 木樁,玩家只會回去升級,不會重新思考 Build。
專業的 Boss 回饋要有:

`預告 → 玩家準備 → 可讀窗口 → 玩家出手 → 明確結果 → 失敗資訊`

goal-gradient 顯示「還差多少」是為了讓玩家知道自己接近成功,
而不是只在倒數結束後告訴他失敗。失敗診斷則要區分時機、組合與數值,
讓下一次嘗試有具體調整方向。

P2「Boss 太像木樁」排在職業、傭兵與敵人之後,因為 Boss 應該檢驗已成形的 Build,
不能在玩家還沒有足夠選擇時先塞進更多懲罰。

##### 為什麼介面要卡片化並保留戰場

卡片不是單純的美術風格,而是把「一個決策單位」包在一起:
名稱、狀態、效果、代價與主要動作應該在同一視覺區塊內。

- 戰場必須保留,因為面板操作的結果要能立刻回到角色與敵人身上。
- 主要動作外露、次要動作收進更多選單,是為了降低誤觸與視覺競爭。
- 鎖定內容要說明條件,因為純 `???` 不會形成目標,只會像尚未完成。
- 已穿裝備仍能直接操作,因為「裝備中」是狀態,不應成為管理功能的死路。
- 手機先驗收,因為空間最小時仍看得懂,桌面才不會只是把混亂攤得更開。

##### 為什麼戰鬥要為真人反應留時間

系統知道狀態在第幾毫秒生效,玩家不知道。玩家需要先辨認訊號、理解意思、決定行動,
最後才按下技能。若整個窗口短於這段認知時間,它就不是技巧,而是預先背答案。

因此關鍵狀態需要:

- 開始訊號。
- 可讀的剩餘時間或進度。
- 接近成功時的強化提示。
- 結束後的結果回饋。

第一次遇到複雜機制可以暫停教學；一般重複事件則保持流動。
暫停是保護閱讀時間,不是降低難度。

##### 為什麼數字要放大但不能改平衡

點擊一直跳 `1`、傷害充滿小數時,即使底層成長正確,玩家仍感覺不到力量提升。
整數較容易掃讀,較大的單擊數字也更符合動作回饋。

但視覺爽感不能偷換成數值膨脹,所以採用玩家傷害與敵人 HP 同比換尺:
改變的是顯示尺度,不是擊殺時間。金幣沒有跟著放大,因為它屬於另一條已驗證的經濟曲線。

##### 為什麼 Game Review 比繼續堆 GDD 更適合目前階段

GDD 適合定義整體規則,但目前問題多半是「實玩後某個環節不成立」。
這類問題需要能排序、指派、討論、驗收與關閉,而不是埋在長文件裡等人重新閱讀。

因此一張 Review 卡就是一個設計 Issue:

- Problem 保留玩家視角,避免只修表面症狀。
- Why 找出系統原因,避免同類問題換地方再出現。
- Solution 定義可執行範圍。
- Expected Result 是實機驗收依據。
- Files 幫工程師快速定位,但不是限制只能修改那些檔案。

卡片進 `review` 代表程式已完成、等待玩家確認；只有使用者驗收後才進 `done`。

1. 先讀本檔「九、交接給 Claude」,確認現況與下一張 Review。
2. 再讀 `docs/視覺效果缺口_給Codex.md`,確認已完成演出與剩餘缺口。
3. 若動玩法規則,讀 `docs/GDD_v3.md` 與 `docs/工程對帳_GDDv3.md`。

5. 若動介面,先讀 `.claude/skills/clicker-ui/SKILL.md`,並以手機實機驗收。
