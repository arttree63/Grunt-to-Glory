### 籃 B:下一 session 直接做(資料現成、不需新裁決)

1. **Boss 內 goal-gradient**(第一優先):打斷進度 %、護盾「還差 N 點破下一層」、
   燃燒/爆燃接近提示。`channelDamage`/`shellValue` 都在 core,只缺 snapshot 欄位 + UI。
   回饋原話:「不是失敗後才告訴他傷害不足,而是過程中讓他知道再多做一件事結果就會不同」
2. **紅點與「還差一點」收斂成三層**(近期一個/本輪一個/跨輪一個)——
   蔡加尼克的反面:現在同屏「差一點」超過十個,是我們自己造的雜訊
3. **失敗診斷分三類**:數值不足 / 時機錯誤 / 組合未完成。
   「只有數值不足的遊戲,會把玩家訓練成不停刷資源」——bossStats 的分帳與打斷資料已夠判類
4. **關聯感串接**(純資料串接,零新系統):傳家之器帶前任持有者名(chronicle 有)、
   列傳補「代表事件」一句話(bossStats 餵)、**人格稱號輕量版**(行為計數 → 稱號:
   傭兵終結多=眾人簇擁者、不放技能=沉默的守望者、最後 5 秒破 Boss=遲來的勝者)
5. **F18 爆燃 core 鉤子**(Codex 交回):燃燒層數/滿層事件 + snapshot,然後 Codex 畫爆燃圓
6. emoji icon 欄位清理(Codex 交回:UI 已全 SVG,core 的 `icon` 欄位是死資料)
