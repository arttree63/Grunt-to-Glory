# 操練系統 MVP 規劃 v0.1

> 《小兵的故事》的成長，不應該是一個數字越來越大，而是一名小兵經過一次又一次操練，
> 逐漸掌握新的戰鬥技巧，最後成為足以改變戰局的戰士。
>
> 因此「操練」不是升級介面的換皮，而是整個角色成長系統的核心敘事與玩法載體。
> 玩家期待的不是下一級，而是**下一次突破**。

---

## 〇、這份文件要幹嘛

不是設計完整系統，是**最小可驗證版本**。要驗證的只有一件事：

**「操練 = 成長」是否真的比傳統升級更有期待感。**

因此範圍刻意壓到最小：一個職業（重裝步兵）、四條操練、每條前 15 級、
不動金幣經濟曲線、不動 Boss 檢定、不加第二種資源。

---

## 一、玩家看到的改變（前後對照）

| | 現在 | 操練版 |
|---|---|---|
| 成長載體 | Hero Lv（一個數字） | 四條操練，各自有等級與里程碑 |
| 成長操作 | 主畫面底部升級條，一直點 | 英雄頁四張操練卡，選一條投入 |
| 成長回饋 | 「Lv.37 → 38」 | 「再 2 級學會旋風斬」 |
| 打斷 | 操練令曾經是全螢幕彈窗 | **一律不彈窗**，全部在英雄頁內完成 |
| 開場 | 六個分頁全開 | 只開「英雄」，第 3 層導引進去操練 |

四條操練（MVP）：

| 操練 | 定位 | 每級給 | 里程碑給 |
|---|---|---|---|
| ⚔ 劍術 | 主要輸出、近戰節奏 | 成長曲線的基礎傷害 | 重擊 → 旋風斬（主動技） |
| 🛡 防禦 | 生存與反擊 | 同上 | 格擋 → 反擊 → 護盾（接 Boss 護盾/打斷機制） |
| 📖 魔法 | 元素附加、控場 | 同上 | 火焰附魔（接現有燃燒層數）→ 冰凍 |
| 🔨 鍛造 | 武器特性 | 同上 | 破甲 → 流血（接現有裝備/鍛造詞綴） |

**原則：四條都會變強，但變強的方式不一樣。** 不能四條都是「攻擊 +X%」，
否則玩家只會查表選最高的那條，Build 就不存在。

## 二、架構決策（先定，執行者不用再想）

### 決策 A：`lv` 不刪，改成「操練總和的衍生值」，對玩家完全隱藏

`lv` 是全遊戲數值的骨架：`heroDPS` 用 `BASE_DMG_PER_LV^(lv-1)` 當主乘區、
`upCost(lv)` 是金幣唯一出口、Boss DPS 檢定與 `tools/balance-sim` 都吃它。
直接刪 = 一次動掉傷害曲線 + 經濟 + 檢定 + 模擬器 + 存檔，爆炸半徑過大，
而且 MVP 要驗的是「期待感」，跟資源換誰付無關。

因此：

```
lv = 1 + Σ(四條操練的等級)
```

- 既有公式**一行都不用改**：投一級操練 = 內部 lv +1 = 原本的成長。
- 玩家端**完全看不到 lv**：主畫面與英雄頁只出現操練等級與里程碑。
- 每條操練除了共同的成長，再給自己的**質性效果**（攻速 / 格擋 / 元素 / 詞綴），
  不再另外加一層 DPS 乘區——避免同一級被算兩次，也避免曲線失控。

**否決的替代方案**：真的刪掉 `lv`、四條操練各自帶乘區。
風險是傷害公式、Boss 檢定門檻、模擬器、251 個測試同時要重寫，
一次改完無法分批驗證；而且四個乘區相乘會讓極端 Build 直接穿透 Boss 檢定。

### 決策 B：MVP 用**金幣**投入操練，不做「經驗 → 操練點」

企劃草案寫的是「打怪 → 經驗 → 操練點 → 分配」。MVP 先不做，理由：

- 金幣現在的**唯一出口就是升級**。改成經驗付費，金幣立刻沒有出口，
  離線收益、掉落、科技三條線全部要重新定價——那是另一個大改版。
- 要驗證的「期待下一個能力」跟付費資源是誰無關。

所以：投入一級操練的成本 = 現行 `upCost(內部總等級)`，曲線零變動。
四條操練共用同一條成本曲線（投哪一條都一樣貴），玩家的選擇是「投哪裡」而不是「投得起嗎」。

**驗證通過後**再談 v0.2 把資源換成經驗/操練點，那時要一起重定金幣出口。

### 決策 C：技能解鎖表是**新資料層**，不動職業技能池

現在技能來源只有職業（`JOBS[jobId].skills` + `awakenSkill`）。
操練里程碑要能「同一種操練、不同職業給不同技能」，所以新增一張表：

```ts
TRAINING_TRACKS[track].milestones = [
  { level: 5, unlock: { kind: 'skill', byJob: { rookie: 'heavyStrike', infantry: 'shieldBash', … } } },
  { level: 10, unlock: { kind: 'passive', id: 'heavyStrikeDmg50' } },
]
```

`availableSkills()` 改為「職業技能 ∪ 操練已解鎖技能」，其餘照舊。
MVP 只填**重裝步兵**那一欄，其他職業留 `rookie` 的預設值，不做假內容。

### 決策 D：分頁鎖是存檔欄位，只擴不縮

新增 `unlockedTabs: string[]`（或等價的旗標），舊存檔遷移時**全開**——
老玩家不能因為改版突然少了五個分頁。新玩家開場只有「英雄」，
其餘依既有觸發點逐步解鎖（裝備：第一件掉落；鍛造：素材夠一次；命運：第 10 層；
旅途：第一個際遇；傳承：第一次可退役）。

### 決策 E：主畫面底部保留一條「投入」快捷

Clicker 需要「一鍵成長」的節奏，全部趕進英雄頁會讓主畫面失去即時回饋。
底部升級條改為**投入當前主修操練**（主修在英雄頁切換），長按連點沿用現有實作。
玩家因此有兩種節奏：主畫面無腦投主修、英雄頁思考要換哪條。

## 三、開場流程（第 1 → 3 層）

1. **第 1 層**：只有英雄分頁；底部只有戰鬥與投入條。玩家先體會「點擊 = 攻擊」。
2. **第 3 層**：金幣已足夠投第一級操練時，聚光燈指向英雄分頁：
   「小兵可以開始操練了」→ 點進去 → 英雄頁四張操練卡，第一次進來只亮劍術與防禦
   （魔法/鍛造在里程碑後解鎖，避免第一眼四選一的決策癱瘓）。
3. 選一條投入 → 卡片立刻顯示「距離下一個能力還差 N 級」。

⚠️ 導引一律走**聚光燈 + 演出**，不再塞說明文字（見 clicker-ui skill 與既有 SpotlightTeach）。

## 四、MVP 驗證目標（做完要回答的四題）

1. 玩家會不會主動打開英雄頁操作操練？（第 3 層導引之後）
2. 玩家會不會開始講「再一級就能學旋風斬」？
3. 不看攻略，光看介面能不能說出四條操練的定位？
4. 期待感是否高於「我又升一級了」？

---

## 五、核心接觸面四問（動工前必答，專案硬規則）

1. **碰哪些核心 model/欄位**：`GameState.lv`（語意改為衍生值）、新增 `trainings`
   與 `unlockedTabs`、`runStats`（操練里程碑要進列傳/成就的話）。
2. **碰不碰現役核心路徑**：碰**成長與金幣出口**（`buy` / `upCost` / `heroDPS` 的呼叫端），
   但**公式本身不動**——只換「誰把 lv 加上去」。Boss 檢定、掉落、轉生不碰。
3. **與計費/額度的關係**：無（單機遊戲，無金流）。
4. **用哪些擴充點**：技能解鎖走新的 `TRAINING_TRACKS` 表 + `availableSkills` 聯集；
   導引走既有 `SpotlightTeach`；分頁鎖走既有 tab 渲染條件。

## 六、施工批次（每批可獨立驗證、獨立回滾）

- **第 0 批・護欄**：先用 `tools/balance-sim` 跑出現況基準（推進速度、金幣、Boss 通過層），
  存成快照。之後每批改完重跑比對——曲線不能因為換介面而漂移。
- **第 1 批・開場收斂**：分頁鎖 + 第 3 層聚光燈導引。不動任何數值。
- **第 2 批・操練資料層**：`trainings` 欄位 + 存檔遷移（`lv` ↔ 操練總和換算）+
  `TRAINING_TRACKS` 表 + `availableSkills` 聯集。UI 先不動，用測試驗證。
- **第 3 批・英雄頁操練卡**：四張卡、里程碑預告、投入按鈕；底部條改投主修。
  舊的升級條與 Lv 顯示同批下線。
- **第 4 批・重裝步兵里程碑內容**：重擊 / 旋風斬 / 格擋 / 反擊 / 火焰附魔 / 破甲 …
  接既有戰鬥事件（燃燒層數、破盾、打斷）才有演出，不做純數字被動。
- **第 5 批・回檢**：模擬器比對第 0 批基準、251 測試、實機從第 1 層玩到第 30 層。
