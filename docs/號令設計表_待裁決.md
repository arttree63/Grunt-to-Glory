# 號令 × 編制 設計表(待裁決)

> 依 2026-08-02 裁決:**號令不是固定技能,是編制的兌現點**。一個按鍵,效果依上場兵種改變。

## 〇、動工前必須知道的引擎限制

| 限制 | 影響 |
|---|---|
| **單一目標**(`enemyHp` 只有一個) | 「左右包夾」「範圍」「彈射」**不能是字面意思**,必須映射成單目標做得到的事 |
| **沒有位置座標** | 站位、繞後、陣型都只能是演出,不可作為邏輯判定依據 |
| 禁止延遲傷害 | 號令的傷害必須同 tick 結算,分段只能是表現層 |
| 破盾值以「命中次數」計 | **每個士兵天然是一次獨立命中**——這是軍團最好用的既有槓桿 |

⚠️ 開出引擎做不到的效果,結果會是「做出來但玩家感覺不到」,那比不做更糟。

## 一、每個兵種要定兩件事

不是只定號令。**常駐**與**號令**要成對,否則玩家在按號令之前感覺不到自己配了什麼。

| | 常駐(部署期間持續) | 號令(消耗全部士兵) |
|---|---|---|
| 現況 | 每 2.4 秒協同一次,先鋒 0.2 秒份、盾衛另計 | 一次總攻,威力 = 1 + 士兵數 × 0.12 |
| 問題 | **兩種兵只有數字差**,玩家分不出來 | **完全不看編制**,配什麼都一樣 |

## 四、衝鋒(英雄技能)與號令的關係

用戶定義:**衝鋒 = 身先士卒,提升士兵戰鬥力數秒**。

這讓兩招從「不重疊」升級成「**有順序關係**」——衝鋒 → 趁 buff 在 → 號令。
那是真正的循環決策,不是兩顆傷害按鈕。

待裁決:

| 問題 | 選項 A | 選項 B | 選項 C | **裁決** |
|---|---|---|---|---|
| 「戰鬥力提升」提升什麼? | 協同傷害倍率 | **協同頻率變快**(2.4 秒 → 更短) | 協同時額外算破盾命中 | |
| 持續幾秒? | 6 | 10 | 與衝鋒冷卻同壽 | |
| 號令在 buff 內施放要不要額外強化? | 是,明確做成連段 | 否,只吃常駐加成 | | |

⚠️ 選 B(頻率)在「傷害 = DPS × 時間」的模型裡是**傷害中性**的,
提升的是**破盾與印記的累積速度**——那是節奏改變而不是數字膨脹,比 A 更符合專案的
power-neutral 原則。但也更難被玩家一眼看懂,需要演出配合。
