# 修訂案 v4.0-A:關卡推進與遠征耐久

> 2026-08-01 · 適用於 GDD v3.0.2 Implementation Baseline
> 本文件只處理**推進結構與血條**。操練系統、職業重規劃、敵人編組另立文件。

---

## 1. 這份修訂案改了什麼

一句話:**戰鬥從「限時 DPS 檢定」變成「限時 DPS 檢定 + 生存檢定」,失敗從「輪次結束」變成「退一層駐守」。**

---

## 2. 推進結構

### 2.1 核心循環

```
推進 → 撞牆 → 退一層駐守 → 掛機累積 → 補構築 → 手動挑戰 → 過關
```

### 2.2 規則

| 項目 | 規則 |
|---|---|
| 進場 | **每一層滿血進場**,耐久不跨層記帳 |
| 失敗 | 退回**上一層**,不扣任何永久進度 |
| 退回後 | **駐守該層**,不自動再挑戰 |
| 再挑戰 | 由玩家按下 `挑戰第 N 層` 按鈕觸發 |
| 駐守期間 | 素材、金幣、經驗**照常產出** |
| 離線 | 不需特殊規則——系統自然停在玩家的真實極限層 |
| 魔王 | 每 10 層魔王,解鎖後可單獨重複挑戰,**不得跳關解鎖** |

> **為何不自動重試**:自動彈跳會讓玩家在牆前反覆失敗數小時,掛機時間變成純浪費。駐守讓掛機時間有產出,且撞牆的決策權回到玩家手上。

### 2.3 UI 必要元素

```
目前最高    87 層
駐守中      86 層

  [ 挑戰第 87 層 ]

上次失敗:後排弓手在你清完前排前造成 68% 傷害
```

⚠️ 失敗原因**必須具體到構築能力**(沿用 § 5.10),禁止只顯示「戰力不足」。

## 3. 遠征耐久(血條)

### 3.1 定位

| | |
|---|---|
| 名稱 | 遠征耐久 |
| 範圍 | **單場戰鬥**,每層滿血進場 |
| 歸零 | 該層失敗 → 退回上一層駐守 |
| 永久損失 | **無** |

### 3.2 兩條檢定各自的職責

血條存在的唯一理由是它問的問題與倒數不同:

| | 問的問題 | 失敗形態 |
|---|---|---|
| **倒數** | 你打得夠快嗎? | 時間耗盡 |
| **耐久** | 你擋得住場上的威脅嗎? | 耐久歸零 |

> 兩者不得重疊。若某機制同時扣時間與扣血,只保留其一。

### 3.3 什麼可以扣耐久

| 來源 | 說明 |
|---|---|
| 敵人攻擊 | 近戰貼身、遠程齊射等,依關卡編組決定 |
| 機制失敗 | 蓄力未打斷、熱度滿、儀式完成 |

> **§ 5.7 的時間懲罰全面改為扣耐久。** 原「剩餘時間 -15%」類設計一律移除,避免兩條檢定互相污染。

### 3.4 護欄

1. 每一次大額扣血**必有預告**(蓄力條、倒數、瞄準線)
2. 扣血機制**必須同時提供破法**(沿用 § 5.7 三種寫法)
3. 耐久上限**不進 DPS 乘區**,不與勳章、祭壇重疊
4. 死亡**不扣任何永久進度**:素材、鍛造計數、圖鑑、勳章全保留

## 6. 驗收標準(補入第十三章)

| 測試 | 標準 |
|---|---|
| **牆的可讀性** | 失敗後玩家能說出「我是被後排射死的」,而非「我戰力不夠」 |
| **駐守有意義** | 駐守一晚後,玩家有足夠資源實質改變構築 |
| **兩軸不重疊** | 存在僅因輸出不足而失敗的關卡,也存在僅因生存不足而失敗的關卡 |
| **無永久懲罰** | 連續失敗 20 次後,玩家的永久進度與失敗前相同 |

## 7. 實作對照(工程盤點,2026-08-01)

### 7.1 空缺 #1「沒有任何事件會結束一輪」——**在現行實作上不成立,可以劃掉**

轉生從來就不是撞牆觸發的:`prestige()`(`src/core/game.ts:2666`)只有一個呼叫者,
就是傳承頁最上方的「退役,讓下一代接棒」按鈕(`src/ui/panels/DestinyPanel.tsx:72`,
掛載於 `src/ui/panels/LegacyPanel.tsx:331`),
條件是 `pendingMedals(s) > 0`(推進到 10 層以上才有勳章可拿)。
撞牆在現行實作只影響「停在哪一層」,不影響輪次結束。
**所以這份修訂案不會弄丟轉生觸發點**——它本來就是玩家主動按的。

### 7.2 「退一層」已經有了,要拿掉的是「自動再挑戰」——**已完成(2026-08-01)**

- Boss 失敗已經是**退回上一層**:`checkBossTimeout`(`src/core/game.ts:1106-1137`),
  註解寫的就是「打不過就退一層」。
- 玩家手動挑戰的入口也已存在:`retryBoss()`(`game.ts:1291`)+ 主畫面 `BossHint`
  (`src/ui/App.tsx:94`),含失敗診斷與戰術三選一。
- **已改**:原本在前一層打完一輪小怪(`MOBS_PER_FLOOR = 3`)就自動彈回 Boss 層
  (`game.ts:711-720`),現在改為**駐守**:不自動再挑戰、也不會越過牆繼續推層,
  金幣素材照常產出,再挑戰只由玩家按鈕觸發。UI 加了「駐守 第 N 層・素材金幣照常產出」。

**正向副作用(等於回答了空缺 #1 的下半段)**:`stallSec` 不再被自動重試清掉
(舊碼 `game.ts:718`),`runStalled()`(`game.ts:2208`,門檻 180 秒)現在會穩定觸發,
「這一代推不動了,可以退役換勳章」的提示終於會準時出現——撞牆與退役動機重新連上,
只是連法從「系統幫你重試到死」變成「你在牆前駐守夠久,系統提醒你該換代了」。
⚠️ 180 秒這個數是在舊模型下訂的,要重新評估。

**數值驗證**:模擬器代理改成會按「挑戰」按鈕(`tools/balance-sim/sim.ts`),
三條命運各六代對照改動前基準,曲線一致(掛機第 1 代 251/231/231、第 6 代 351/291/321,
對照基準 251/…/301),確認這批是 UX 改動不是數值改動。
⚠️ 過程中兩次踩到「代理寫錯 → 假數據」:
(1) 用 `killsInFloor >= 3` 當條件,但那個計數每 3 隻就歸零,條件永遠不成立 → 模擬器在牆前空轉;
(2) 改成「立刻重挑戰」→ 代理不 farm 就衝,一分錢賺不到,純掛機死鎖在第 11 層。
最後採「打滿一輪小怪再挑戰」,才對得上舊節奏。順手修掉 `shield-check.ts` 用
「floor 變了」判擊破的假數據(失敗會讓 floor 變小,會被誤記成擊破)。

### 7.3 目前沒有任何東西會傷害玩家(耐久要從零長)

一般層(非 Boss)**沒有失敗的可能**,唯一的失敗是 Boss 的 30 秒 DPS 檢定(`BOSS_TIME = 30`)。
core / render / 美術資產三層都沒有「敵人攻擊玩家」的任何表達(怪物只有 idle 四張圖)。

### 7.4 §3.3「時間懲罰全面改扣耐久」在程式碼裡其實只有一條

盤點結果:全 codebase 唯一會改變 `bossTimeLeft` 流速的機制是**圖騰**
(`TOTEM_TIMER_MULT = 1.5`,`game.ts:809`)。GDD 寫的「熔爐熱度滿 → 剩餘時間 -15%」、
「時鐘祭司週期加速倒數」**只存在於文件,程式碼沒有實作**。
所以這一條改起來比想像小:圖騰改成扣耐久即可,其餘是純文件層改寫。
⚠️「熱度」一詞已被鍛造系統佔用(`forgeHeatMaterials`),新機制別再用這個字。

### 7.6 盤點順手撿到的既有問題(與本修訂案無關,但會影響驗收)

   耐久歸零的失敗會讓這句變成謊話;`core.test.ts:1862` 還斷言了這個字串。
