# 第一章 遊戲定位與核心循環

## 1.1 定位

- **類型**:點擊放置 RPG(Clicker / Idle RPG)
- **平台**:Web/PWA → CrazyGames → Capacitor 雙平台手遊
- **核心樂趣**:無名雜兵 → 傳奇英雄的成長反差;構築選擇改變戰鬥行為;跨代傳承留痕
- **主角永遠是戰鬥核心**(與點擊泰坦後期主角邊緣化明確區隔)

## 1.2 核心循環

```
[ 無名小兵 ] → [ 點擊 / 自動擊殺 ] → [ 金幣、經驗、素材 ]
      ▲                                    │
      │                                    ▼
[ 退役 / 傳承 ] ← [ 極限爬塔撞牆 ] ← [ 升級 / 命運 / 轉職 / 鍛造 ]
```

## 1.3 下一階段設計方向(v3 核心)

> 遊戲已回答「為什麼我要繼續成長」。
> v3 必須回答:**「為什麼我想親眼看下一場戰鬥會發生什麼」**。

具體轉向:

```
敵人提出時間與構築問題
  → 玩家用自動施放策略表達意圖
    → 不同職業以不同資源規則解題
```

**明確拒絕**:再增加成長頁面或純數值內容。先補 Tier3 或大量職業內容,只會把更多內容放進同一個木樁戰鬥。

## 1.4 點擊的定位(v3.0.1 修正)

> ⚠️ **事實更正**:GDD v2 § 2.3 原則為「點擊不另計傷害」,但實作已改為**一次點擊 = 一次揮砍 = 一次跳字 = 一次扣血**,因為實測發現「點了沒打到東西」體感極差。v3.0.1 **確認保留直接傷害**,但明確定義其縮放方式。

### 為何保留直接傷害

原則「點擊不另計傷害」的動機是正確的——點擊傷害在指數成長下必然貶值成廢數值(點擊泰坦後期即如此)。但正確解法不是取消傷害,而是**設計它的稀釋方式**,讓它永遠有體感、永遠不成為必要成長軸。

### 縮放規則(v3.0.2 修正 —— 原公式為算術錯誤)

> ⚠️ v3.0.1 寫「每次點擊 = 當前 DPS × 0.5 秒」。**該公式未計入點擊頻率**:每秒點 4 次即為 +200% DPS,手速直接成為最強成長軸,徹底違反「不點就過不了」禁令。已修正。

**採低單次價值 + 每秒預算上限:**

```
clickDamageBudgetPerSecond = heroDPS × 0.2      // 每秒上限 = 20% DPS
單次點擊傷害 = heroDPS × 0.05 秒                 // 每次扣除本秒預算
```

- 每次點擊從**本秒預算**中扣除;預算用盡後的點擊仍提供戰意、觸覺與視覺回饋,但**不追加直接傷害**
- 用「每秒預算」而非「每秒次數上限」,是為了防止高刷新率、自動連點與巨集突破上限
- **不設點擊傷害相關的升級、詞綴或天賦**——避免它變成第二條成長軸
- 掛機玩家的落差上限為 20% DPS(約 1.3 層),符合「掛機不受懲罰」
- 點擊直接傷害**受弱點窗口倍率影響**(刻意如此,窗口是點擊主場),但每秒預算仍以基礎 DPS 計算

### 對內購的影響(Phase 3)

「自動點擊助手」的定位因此明確為**便利而非強度**:它讓玩家自動達到每秒預算上限,但不能超過。付費買到的是省手指,不是變強——內購不破壞平衡。

### 點擊的主要價值(三處)

1. **弱點窗口**——窗口開啟時戰意衰減停止、累積加倍。這是全遊戲唯一「手動介入改變勝負」的時刻
2. **素材產出**——素材不隨 1.16^層 貶值,是唯一價值永不衰減的獎勵
3. **集火目標指定**(待裁決,見附錄 C)

⚠️ 調校鐵則:點擊應把「差一點過不了」變成「過」,而非「不點就過不了」。配裝正常的掛機玩家仍應能通過。

### 需驗證項目(列入 § 0.4 對帳)

點擊代理感、揮砍動畫與傷害是否同步、窗口外點擊是否仍有意義、素材獎勵是否足以維持操作價值。

## 2.3 ⭐ 三職業資源差異化(方案 B1,定案)

**問題**:三職業目前共用「累積印記 → 引爆 → 冷卻回轉」骨架,技能名稱不同但玩法相同。用「專屬演出」解決是把機制問題當美術問題——做完會看起來不同、玩起來一樣。

**方案**:保留共用骨架,差異放在**資源的消耗規則**。採 B1(中成本),不引入場地座標與元素狀態機。

### 2.3.1 重裝步兵:陣位槽(空間型)

不做自由空間位置,改用**三個抽象陣位**:前陣 / 中陣 / 後陣。

**陣位生成規則**(v3.0.1 補定義):

| 情境 | 建立哪個陣位 |
|---|---|
| 預設 | 前陣 → 中陣 → 後陣 循環 |
| 護盾存在時 | 優先建立前陣 |
| 弱點即將開啟 | 優先補齊缺少的陣位 |
| 三陣齊備時再建立 | 強化最早建立的陣位 |

**陣位生命週期**(必須明定,否則工程只能推測):

| 項目 | 規則 |
|---|---|
| 存在時間 | **有限**(暫定 15~25 秒,依技能等級;具體值待模擬) |
| 跨普通層 | **不清除**(允許在前一層尾段布陣後帶進 Boss 戰) |
| Boss 階段轉換 | 不清除 |
| 軍陣號令消耗 | **消耗全部陣位**,引爆效果依消耗時的組合判定 |

> 「存在時間有限 + 跨層不清除」的組合是刻意設計:玩家無法永久掛著三陣進 Boss,必須在進戰前約 20 秒內完成布陣 → 產生「現在消耗還是留著進 Boss」的真實決策,也正是重裝在弱點窗口具優勢的來源。

- 盾牆突擊依上表規則建立一個陣位
- 軍陣號令依**目前陣位組合**引爆:

| 陣位狀態 | 引爆效果 |
|---|---|
| 1 個陣位 | 單次重擊 |
| 2 個不同陣位 | 兩段衝擊 |
| 3 陣齊備 | 堡壘爆發 或 延長弱點窗口 |

視覺上為三個固定地面區域,不需完整位置模擬與碰撞判定。

**玩家的問題**:「我完成了哪些陣位?現在消耗還是繼續布陣?」

### 2.3.2 突擊斥候:破綻數量(累積型)

- 疾影穿刺累積破綻層數
- 追風印記依**層數**決定連擊段數(層數越高,獨立攻擊事件越多)

**玩家的問題**:「累積多少破綻,消耗成多少次攻擊?」

### 2.3.3 隨軍法警:法令來源順序(序列型)

**不使用元素分類**(元素法典為新增系統,列 P1 再議)。改為依**最近三枚法令的來源順序**決定律令標記的引爆形態。

**首版三種法令來源**(v3.0.1 修正:第三來源改為機制事件,不用抽象的「命運」):

| 來源 | 生成事件 |
|---|---|
| 技能法令 | 主動技能施放 |
| 裝備法令 | 傳說或套裝行為觸發 |
| **機制法令** | 印記滿層 / 弱點開啟 / 破盾 / 共鳴觸發 |

> 原「命運法令」不可實作——命運節點多為長期規則,不週期性產生事件,工程無法判斷何時生成。

**命運只負責改造「哪些機制事件可以生成法令」**:

| 命運 | 額外生成規則 |
|---|---|
| 神匠 | 裝備特性首次觸發時額外生成一枚 |
| 戰術家 | 完成指定施放順序時額外生成一枚 |
| 尋寶獵人 | 取得或消耗遺物時額外生成一枚 |

> ⚠️ **不使用「傭兵法令」作為首版第三來源**——傭兵排在 P1,若採用會導致「三種來源各一」在 P0-B 永遠湊不到。傭兵法令於 P1 加入為第四來源。

引爆形態範例:

| 順序 | 形態 |
|---|---|
| 技能 → 技能 → 裝備 | 集中裁決 |
| 裝備 → **機制** → 技能 | 延遲連判 |
| 技能 / 裝備 / 機制 各一 | 大審判 |

**來源型別**(命運不進入此 enum,僅修改生成規則):

```ts
type DecreeSource =
  | 'skill'
  | 'equipment'
  | 'mechanic'
  | 'mercenary';   // P1 才啟用
```

**玩家的問題**:「用什麼順序排列法令,最後轉成哪種裁決?」

## 2.4 ⭐ 技能自動施放策略(P0 前置系統)

### 2.4.1 為何必須有

本作為自動戰鬥,技能冷卻到就自動施放,玩家無即時操作介面。因此**任何要求「玩家抓時機」的設計都無解**。

施放策略把時機從**執行層**搬到**配裝層**:玩家決定的是政策,不是手速。設定一次長期有效,掛機玩家完全不受影響。

**蓄力打斷型與弱點爆發型 Boss 都必須靠它才成立。**

### 2.4.2 首版採預設策略模板,不做自由條件編輯器

自由條件組合會演變成完整條件編輯器,工程與 UI 成本對放置玩家過重。

**每個技能提供企劃預先定義的 2~4 個有效策略。** 範例:

| 技能 | 可選策略 |
|---|---|
| 軍陣號令 | 立即施放 / 軍勢滿層 / 弱點開啟 / 軍勢滿層或保留超時 |
| 追風印記 | 立即施放 / 印記滿層 / 護盾存在時 / 弱點開啟時 |
| 律令標記 | 立即施放 / 法令滿層 / 破甲後 / 弱點開啟時 |

### 2.4.3 每個保留策略必須自帶 fallback

不採用全域「15 秒強制施放」——Boss 可能在第 16 秒才開弱點,技能會提前浪費;且不同技能冷卻與價值不同,不能共用固定時間。

**格式**:`若 [主條件],否則 [次條件] 時施放`

範例:
- 弱點開啟時施放,否則印記滿層時施放
- 護盾破除後施放,否則 Boss 蓄力時施放

**最大保留時間 = 該技能基礎冷卻的 20%~30%**,並設全域上下限。不寫死秒數。

### 2.4.4 護欄

| 規則 | 理由 |
|---|---|
| 預設全為「立即施放」 | 不設定的玩家不受任何懲罰(心理契約一) |
| 同時最多 2 格可設為保留型 | 避免全保留造成輸出真空 |
| 策略跨轉生保留 | 屬配裝層設定 |
| 不影響 power-neutral 預算 | 策略改變時機,不改變總量 |

### 2.4.5 解鎖節奏(本身是期待載體)

一轉解鎖第 1 格策略 → 命運關鍵節點解鎖窗口型與狀態型條件 → 二轉全開 → 戰術家命運額外解鎖順序型。

## 2.5 命運系統

### 2.5.1 三條命運

**神匠 / 尋寶獵人 / 戰術家**。各階段節點**二選一**,選定後另一節點本輪關閉。

**命運節點是機制,不是數值。** 寫「攻擊 +5%」的節點會讓唯一解問題重新出現。

### 2.5.2 命運傾向 = 身份

每次選擇累積傾向印記,用於決定:二轉候選、特殊旅途事件、傳承稱號、裝備變體、該輪結局文字。

呈現方式不是「你選了三個節點」,而是:

> 神匠傾向:3
> 你的武器開始留下歷代鍛造痕跡。
> 下一階段可能形成:鐵壁工匠。

### 2.5.3 命運改造資源的方式

| 命運 | 對三職業資源的改造 |
|---|---|
| 神匠 | 資源可繼承一條裝備特性 |
| 戰術家 | 資源依施放順序改變效果 |
| 尋寶獵人 | 資源可攜帶本輪遺物效果 |

## 2.6 二轉逐步揭露

不到 Lv.100 才公布,讓玩家在達成前就看見職業正在被命運改造:

| 階段 | 呈現 |
|---|---|
| 一轉當下 | 三個**模糊未來輪廓**(防禦型/攻城型/鍛造型),不公布名稱 |
| 第一個命運節點 | 「命運正在偏向鍛造系」,一個輪廓亮起 |
| 第二個節點 | 揭露名稱、被動概念、技能圖示、外觀剪影、還差哪個條件 |
| 二轉達成 | 「**你在這一輪做出的選擇,塑造了這個職業**」 |

## 2.7 武器類型

| 武器大類 | 職業線 | 攻擊演出(背後視角) |
|---|---|---|
| 劍/盾類 | 重裝步兵 | 近戰揮砍 |
| 弓/弩類 | 突擊斥候 | 舉弓拉弦,箭矢射向怪物 |
| 法杖/魔導具 | 隨軍法警 | 舉杖前推,法陣展開 |

# 第三章 裝備與鍛造

## 3.1 四層架構

| 層級 | 玩家的問題 | 功能 |
|---|---|---|
| 白裝 | 這個基底適合打造什麼 | 乾淨基礎 |
| 藍/紫裝 | 我現在缺什麼數值 | 數值與過渡 |
| 傳說(金) | 我想讓技能怎麼改變 | **單件改造玩法** |
| 套裝標籤 | 我想完成什麼流派 | **完整機制循環** |

核心公式:**白裝定基底,黃裝補數值,傳說改技能,套裝定流派,傳家之器跨輪保留玩法記憶。**

## 3.2 取得方式

怪物只掉素材,**裝備一律由鐵匠鋪產出**。

| 層級 | 取得 |
|---|---|
| 白裝基底 | 普通鍛造;基底類型受投入素材種類影響 |
| 藍/紫裝 | 普通鍛造主要產出 |
| 傳說 | 精工鍛造,受 50 次保底計數保障(計數器常駐可見) |
| 套裝標籤 | 精工鍛造投入部位素材 + 菁英素材時有機率附加;鐵匠鋪等級提升機率 |

## 3.3 素材體系

| 素材 | 來源 | 鍛造效果 |
|---|---|---|
| 怪物素材 | 所有怪物 100% | 隨機部位、隨機品質 |
| 部位素材 | 每 10 層 Boss | 鎖定部位 |
| 菁英素材 | 寶箱怪 / 每日首殺 Boss 保底 / 轉生商店 | 品質下限保證(紫以上) |

**不設傳奇素材**——菁英素材是唯一保底券,避免保證階級通膨。

Boss 部位素材輪替:X10 頭部 / X20 武器 / X30 身體 / X40 鞋子 / X50 飾品(循環)。

## 3.4 裝備結構三層

```
基底(單手劍/塔盾/法杖…)   ← 不可變
普通詞綴(攻速/暴擊/冷卻)    ← 可重鑄
傳說特性(改變技能行為)      ← 固定,不可洗掉
```

- 部位 **5 格**:武器 / 頭盔 / 鎧甲 / 鞋子 / 飾品
- 品質六階:白 → 綠 → 藍 → 紫(菁英)→ 金(傳奇)→ 暗紅(神器)
- 有效詞綴控制在 12~16 種,分四類:輸出 / 循環 / 範圍 / 經濟

## 3.5 ⭐ Power-Neutral 原則

> **傳說與套裝效果必須 power-neutral:單件淨輸出增益上限 ±10%。差異來自「怎麼打」,不是「打多少」。**

流派間差距須維持 **15~25%**。

### ⭐ 兩種測試環境(v3.0.1 新增)

單一「±10%」標準會讓針對性裝備失去存在理由——分身拆盾、蓄力利用窗口、燃燒破解狀態,**本來就該在對應 Boss 上更有效**,否則玩家沒有換裝動機。

| 環境 | 標準 | 驗證什麼 |
|---|---|---|
| **中性木樁測試** | 單件淨 DPS 差異 **±10% 內** | 不靠純倍率變強 |
| **適性 Boss 測試** | 針對性傳說可帶來 **10~25% 機制效率提升** | 配裝確實有意義 |

提升必須來自拆盾效率、窗口利用或狀態破解等**機制途徑**,不得來自傷害倍率。其他傳說仍須能通過,只是效率較低。

上線檢核(每件傳說/套裝):
1. 中性木樁「有 vs 無」對照,淨 DPS 差異落在 ±10% 內
2. 適性 Boss 上機制效率提升落在 10~25%,且非針對性構築仍可通過
3. 三職業滿配互比,差距落在 15~25%
4. 超標時**優先削弱數值而非移除機制**——機制是它存在的理由

## 3.6 傳說裝合格門檻

> **每件核心傳說必須回答:穿上之後,戰鬥畫面會多發生什麼?**

| 合格 | 不合格 |
|---|---|
| 產生分身 / 敵人燃燒 / 審判分三次落下 / 暴擊生成飛刃 / 留下火焰地面 / 軍旗複製下一個技能 / 傷害儲存滿後爆發 | 傷害 +30% / 暴擊傷害 +50% / Boss 傷害 +20% / 攻速提高 / 冷卻縮短 |

右欄可作為一般詞綴,**不得佔用傳說特性位置**。

### 三層回饋(每件傳說皆須具備)

| 層 | 作用 | 範例 |
|---|---|---|
| ① 觸發前提示 | 讓玩家知道即將發生 | 分身輪廓浮現 / 武器開始燃燒 / 軍旗圖示充滿 |
| ② 觸發行為 | 真正發生不同事件 | 分身出現 / 火焰爆發 / 落雷 / 砲台開火 |
| ③ 結果痕跡 | 觸發後短暫留痕 | 燃燒狀態 / 地面裂痕 / 殘影 / 標記 |

> 只有大字與震屏,等於只做了第 ② 層,且所有技能長得一樣。

## 3.7 強度分層

| 層 | 來源 | 可否淨增益 |
|---|---|---|
| 第一層 | 傳說裝 | ❌ power-neutral(例:雙生影刃——本體 70% + 分身 30%,總量不變但變雙行動者) |
| 第二層 | 套裝 | ⚠️ 有限。增加行動者數量、節奏、觸發條件、視覺規模,不給誇張倍率 |
| 第三層 | 命運 / 二轉 | ✅ 可淨增益(角色成長預算),仍納入 15~25% 模擬 |

> 確保早期掉一件傳說就能看到「玩法變了」;後期二轉仍有更強版本可期待。

## 3.8 套裝:標籤制

- **每套 3 件**(裝備僅 5 格,3 件才能保留其他格位裝單件傳說)
- 2 件建立基礎機制 / 3 件完成質變
- **不綁定固定部位**:任何裝備都可能帶套裝標籤,穿滿同標籤即啟動
- 套裝提供**機制拼圖**,不提供純倍率

### 首版 2 套

**帝國鐵壁**(重裝系)
- 2 件:盾類技能留下軍陣標記;不同盾類技能留下不同標記
- 3 件:三種軍陣標記組成帝國堡壘,週期性複製最近一次非盾類技能

**戰術指揮官**(通用,對應戰術家)
- 2 件:連續施放不同技能時記錄其順序
- 3 件:完成預先顯示的順序後,最後一個技能轉化為特殊形態並刷新指令

### 套裝與傳說必須互相強化

> **套裝建立骨架,單件傳說決定版本。** 同一套裝應至少有 2~3 種傳說搭配方向。

## 3.9 鍛造限次與保底

- **普通鍛造不限次**(保留日常開錘爽感)
- **精工鍛造每輪 3 次**,決策感集中在高價值鍛造;次數可用勳章擴充
### 雙保底(v3.0.1 修正)

單一 50 次保底在每輪 3 次的限制下,最差需約 17 輪才觸發一次——目標過遠,計數器無法形成接近感,反而變成無感數字。

| 保底 | 條件 | 保證內容 |
|---|---|---|
| **短保底** | 精工累計 **12 次**未出傳說特性 | 必出**帶傳說特性**的裝備(約 4 輪內) |
| **長保底** | 精工累計 **50 次** | 必出帶**套裝標籤或指定部位**的傳奇 |

- **普通鍛造每 10 次推進 1 點精工保底計數** —— 讓掛機玩家也持續接近目標
- 兩個計數器**皆常駐可見**(「距離必出傳說特性:5 次」/「距離指定傳奇:37 次」)
- 「未出傳說特性」而非「未出傳奇」——玩家真正在等的是玩法改變,不是品質階級

# 第四章 戰鬥事件庫與狀態共鳴

## 4.1 玩家側戰鬥事件庫

技能最終都呼叫 `dealDamage(value)` 的結構無法做出玩法差異。拆為可組合事件:

```ts
type CombatEvent =
  | 'SpawnAlly' | 'DespawnAlly' | 'MoveEntity'
  | 'ApplyStatus' | 'StackStatus' | 'ConsumeStatus' | 'TransformStatus'
  | 'CreateZone' | 'RepeatAttack'
  | 'DelayDamage' | 'DeferDamageWindow' | 'ReleaseDeferred'
  | 'StoreDamage' | 'ReleaseStoredDamage'
  | 'CreateMark' | 'ConsumeMark' | 'ChainEvent'
  | 'AdvanceCooldown' | 'RecordSequence' | 'GrantRelic';
```

組合範例:

```
盜賊背刺 = DespawnAlly → MoveEntity(背後) → dealDamage → CreateMark → MoveEntity(返回)
火焰爆燃 = ApplyStatus(燃燒) → StackStatus ×N → [滿層] → CreateZone(爆炸) → ConsumeStatus
冰霜凍結 = ApplyStatus(凍結) → DeferDamageWindow(2s) → ReleaseDeferred
```

⚠️ **敵人側元件庫必須分離**(見 § 5.2),兩者僅共用機制關鍵字作為描述語言。

## 4.2 九種行為原型

企劃寫新內容時由此表選型,不自創類別。

| # | 行為 | 首版狀態 |
|---|---|---|
| 1 | 分身 | ✅ |
| 2 | 狀態(燃燒等) | ✅ |
| 3 | 場地物件 | ✅ |
| 4 | 蓄力與爆發 | ✅ |
| 5 | 位移攻擊 | ✅(傭兵) |
| 6 | 凍結/時間 | ✅(傭兵) |
| 7 | 範圍 | ⚠️ 僅表現層(形狀語言先行) |
| 8 | 連鎖/彈射 | P1 |
| 9 | 狀態轉化 | P1(深度來源) |

## 4.3 四種通用狀態

| 狀態 | 規則 |
|---|---|
| 燃燒 | 持續造成效果、可疊層、可提前引爆 |
| 凍結 | 延後結算、可被重擊碎裂、Boss 有抗性與內建冷卻 |
| 標記 | 指定後續攻擊行為,可由本體/分身/傭兵消耗 |
| 破甲 | 多段累積,達標開啟重擊窗口 |

### ⭐ 延遲的兩種類型(v3.0.1 新增,解決與附錄 B 的衝突)

v3.0 同時規定「凍結延後兩秒結算」與「延遲類在 Boss 戰內立即結算」,工程無法判斷 `DelayDamage` / `DeferDamageWindow` 該如何處理。**延遲必須拆為兩類:**

| | **表現延遲** | **機制延遲** |
|---|---|---|
| 邏輯結算 | **命中時即完成** | 條件成立才結算 |
| 畫面 | 血條動畫暫停、傷害數字延後、解除時集中播放總額 | 依實際結算播放 |
| 用途 | 凍結、時間停止 | 延遲審判、儲存爆發 |
| 弱點窗口倍率 | 以**命中時**計算 | 以**釋放時**計算 |
| 破盾值 | 以命中時計(各 4 點) | 以釋放時計 4 點(單次重擊) |
| Boss 血量歸零 | **即刻判定通過**,動畫可繼續播放 | 同,以釋放結果判定 |
| 戰鬥結束未釋放 | 不存在此情況 | **強制結算**(不使玩家因帶延遲裝備在限時檢定下純虧) |

> **凍結一律採表現延遲。** 這解決了關鍵風險:若採機制延遲,可能出現「倒數結束前明明已造成足夠傷害,卻因尚未播放解凍而判定失敗」。
>
> 機制延遲的倍率以**釋放時**計算,自然形成「窗口外蓄力、窗口內釋放」的正確激勵,且不需要玩家手動操作(由施放策略完成)。

### 凍結的具體實作

本作無玩家 HP,Boss 是純限時 DPS 檢定,因此「凍結」在機制上**沒有防禦意義**,唯一能作用的對象是倒數——而倒數是唯一勝負判定。暫停 2 秒 = 白送 6.7% DPS,直接突破 power-neutral。

**正確實作**:

```
ApplyStatus(凍結)  → 畫面褪色、Boss 停格、冰晶生成
                    → 傷害在邏輯層【立即結算】,扣除 Boss 生命
                    → 僅【血條動畫、傷害數字、命中演出】延後播放
解除時              → 冰裂,血條追幀,彙總數字一次呈現
```

> ⚠️ **不建立 deferred damage buffer。** 倒數照常進行,傷害在邏輯層立即結算;只有演出延後。
> 若採機制延遲,會出現「倒數結束前明明已造成足夠傷害,卻因尚未播放解凍而判定失敗」——這是採表現延遲的全部理由。

附加護欄:Boss 每場觸發上限 2 次、內建冷卻、凍結期間玩家技能冷卻照常進行。

## 4.4 四種共鳴

| 共鳴 | 條件 |
|---|---|
| 爆燃 | 燃燒達門檻後由重擊或特定技能提前引爆 |
| 碎裂 | 凍結狀態受單次重擊時產生額外事件 |
| 蒸氣 | 燃燒目標被凍結時生成範圍蒸氣爆發 |
| 影襲 | 帶標記敵人被分身或背刺命中時延長弱點窗口 |

首次觸發顯示「**發現共鳴:碎裂**」並登錄圖鑑。

## 4.5 ⭐ 共鳴可達路徑表(必填,含取得時序)

「理論上能湊到」不等於「一輪中能合理湊到」。每個共鳴必須檢查:來源在第幾層可得、是否同屬互斥命運節點、是否佔用同一裝備部位、是否需要兩件互斥傳說、是否在目標 Boss 之後才掉、是否依賴二轉後內容。

| 共鳴 | 最早成形 | 路徑 A | 路徑 B | 互斥風險 |
|---|---|---|---|---|
| 爆燃 | 約第 30 層 | 裁決餘燼 + 法警引爆 | 火術士 + 重擊傳說 | 否 |
| 碎裂 | **待補** | 冰法師 + 法警重擊 | **凍結傳說 + 蓄力技能(來源缺)** | 目前缺凍結裝備源 |
| 蒸氣 | **待補** | 燃燒傳說 + 冰法師 | 火術士 + 凍結傳說(來源缺) | 目前缺凍結裝備源 |
| 影襲 | 約二轉後 | 雙生影刃 + 斥候標記 | 影陣先鋒 + 盜賊 | 部分較晚 |

### 強制規則

> **每一種狀態至少需有一個「非傭兵」來源。** 傭兵一次只能帶 1 隻,若共鳴的所有來源都在傭兵欄位,該共鳴永遠不可達成。

**必須補**:凍結類**通用傳說**至少 1 件(建議通用而非職業專屬,避免綁死職業或命運)。未補則碎裂與蒸氣皆為死機制。

## 4.6 機制關鍵字(17 種)

**關鍵字 = 名詞**(玩家在裝備卡片與篩選看到的標籤);**事件 = 動詞**(程式執行單元)。

完整對照見附錄 A。強制規則:

1. 每個關鍵字至少對應一個事件;新增關鍵字必須同時定義事件對應
2. 裝備 `mechanicTags` 為 enum,值域 17 種,**禁止自由字串**
3. 事件庫新增事件時,若無關鍵字可歸屬,必須先補關鍵字再實作
4. 共鳴判定以**關鍵字**為條件,不以事件為條件

# 第五章 敵人與構築檢定

## 5.1 核心原則

敵人難度**不來自攻擊玩家**(無玩家 HP,不得引入受傷/殘血/回血/死亡復活),而來自**干擾玩家的輸出結構**。

> **Boss 不是要殺死玩家,而是要讓玩家的構築遇到問題。**

**鐵則:所有檢定必須在配裝層可解,不得要求執行層操作。**

| | 範例 |
|---|---|
| ✅ 配裝層可解 | 「你有沒有帶蓄力型傳說」「你的構築有沒有多段事件」「你的施放策略有沒有對準窗口」 |
| ❌ 執行層要求 | 「你有沒有在對的時機手動放技能」「你有沒有手動輪替技能」 |

## 5.2 敵人側機制元件庫(與玩家側事件庫分離)

```ts
type BossComponent =
  | 'HitCountShield'        // 多層護盾,依破盾值拆除
  | 'TimedWeakPoint'        // 週期弱點窗口
  | 'DamageThresholdArmor'  // 單次傷害門檻(相對值)
  | 'CastInterrupt'         // 蓄力,期間達門檻可中止
  | 'SpawnTarget'           // 召喚圖騰/部位/幻影
  | 'StatusRequirement'     // 需累積狀態層數才崩解
  | 'PhaseTransition'       // 階段變化
  | 'TimePenalty'           // 時間懲罰(須配破法)
  | 'EfficiencyDebuff'      // 降低某類效率(取代 SkillLock)
  | 'DiversityBonus';       // 機制多樣性獎勵(取代 AdaptiveResistance)
```

**Boss = 1~2 個元件組合。**

## 5.3 Boss 原型

| 原型 | 行為 | 檢查 | 狀態 |
|---|---|---|---|
| ① 護盾型 | 週期性多層護盾;多段攻擊快速拆除;拆完進入弱點期 | 多段、攻速、分身、持續傷害 | **P0-A** |
| ② 弱點爆發型 | 週期開放弱點窗口,窗口內傷害倍增 | 爆發、蓄力、延遲 | **P0-B** |
| ③ 蓄力打斷型 | 週期蓄力,需於期間達成傷害或事件數門檻 | 高頻或高爆發(門檻二選一皆可達成) | P1 |
| ④ 部位型 | 依序出現不同弱點,由攻擊類型自動判定 | 構築多樣性 | P1(需多目標) |
| ⑤ 圖騰型 | 召喚場地物件改變戰場規則 | 範圍、連鎖、傭兵 | P1(需多目標) |
| ⑥ 階段變化型 | 不同時間點改變規則 | 綜合 | P1 |
| ⑦ 多樣性獎勵型 | 構築關鍵字種類越多,傷害加成越高 | 機制多樣性 | P2 |

### 已否決的設計

| 設計 | 否決理由 | 替代 |
|---|---|---|
| **SkillLock**(封印技能格) | 自動戰鬥下純懲罰無解;技能格是玩家身分載體 | `EfficiencyDebuff`:該格技能效果 -40%,擊破圖騰恢復 |
| **AdaptiveResistance**(對重複機制產生抗性) | 玩家無法輪替,純分身流會被平白削弱 | `DiversityBonus`:獎勵多樣性而非懲罰專精(見下) |

### DiversityBonus 必須是機制收益,不是傷害百分比(v3.0.2 修正)

原設計「5 種關鍵字 +15% / 7 種 +30%」本質仍是「堆越多標籤傷害越高」,會讓玩家為湊標籤帶大量低關聯裝備,形成新的標準答案。

| 關鍵字種類 | 效果(機制型) |
|---|---|
| 3 種 | 正常戰鬥 |
| 5 種 | Boss 弱點**提早 1 秒**開啟;移除一層特殊護盾 |
| 7 種以上 | 第一次弱點關閉時**延長 1.5 秒**;本場免除一次時間懲罰 |

亦可採:不同關鍵字首次觸發時削減 Boss 儀式進度。

## 5.4 ⭐ 破盾值系統(取代小數層數)

玩家不易理解「這次燃燒拆了 0.25 層」。底層改用**破盾值**,UI 換算為完整層數。

| 來源 | 破盾值 |
|---|---|
| 獨立命中(普攻/技能/分身/砲台/傭兵) | **4 點** |
| 狀態週期 tick(燃燒等) | **1 點** |
| 延遲引爆 / 蓄力釋放 | 4 點(視為單次重擊,不因累積量增加) |
| 範圍攻擊命中多目標 | 對單一護盾仍計 4 點 |

- **每 4 點破一層**
- 畫面顯示完整護盾片破裂,**不顯示小數**

### 每秒上限必須由模擬推導 ⚠️

不可硬編碼 16 點/秒。若上限等於 4 次獨立命中,**分身流會與燃燒流撞到同一道天花板**——雙生影刃在 P0-A 的全部價值就是「分身讓拆盾更快」,若一上場就頂到上限,P0-A 等於無法驗證自身假設。

> **規則:上限由模擬反推,使一般配置落在上限的 50~60%**,留出讓多段/分身構築真正受益的空間。此值寫入 game-balance skill,不寫死在程式。

### 計數必須用明確欄位,不看函式呼叫次數

一個技能可能內部呼叫多次 `dealDamage` 但玩家認知上仍是一擊;反之本體與分身應算兩個攻擊者。

```ts
interface HitEvent {
  hitEventId: string;      // 玩家認知上的「一擊」
  sourceEntityId: string;  // 本體 / 分身 / 砲台 / 傭兵
  shieldHitValue: number;  // 破盾值
}
```

> 否則未來技能重構會意外改變拆盾效率。

## 5.5 ⭐ 相對門檻:採靜態預估,不採戰鬥中即時採樣

指數成長(HP ×1.16/層)+ break_infinity 之下,絕對數值門檻幾層內就變成必過或必不過。但**戰鬥中即時採樣**也不行,會產生反直覺結果:

- 玩家換上更強裝備後門檻同步提高
- 蓄力流因前 10 秒未爆發被判定為低平均
- 玩家可刻意壓低前 10 秒輸出讓門檻下降
- 不同施放策略使基準不穩定

### 正確做法:進戰前依裝備、技能、傭兵靜態計算

```ts
interface BuildEstimate {
  estimatedAverageHit: number;   // 預估平均單擊
  estimatedHitRate: number;      // 預估每秒事件數
  estimatedBurstDamage: number;  // 預估 5 秒爆發
}
```

| 門檻 | 公式 | 上下限 |
|---|---|---|
| **行為分類門檻**(哪些攻擊算「重擊」) | `estimatedAverageHit × 3` | — |
| **Boss 耐久門檻**(核心需累積多少重擊值) | 依 Boss 層數、類型與成長曲線計算 | clamp 至 Boss 最大生命 2%~8% |
| 蓄力打斷門檻 | `Boss 最大生命 × 12%` | — |
| 時間扣除 | `剩餘時間 × 15%` | — |
| 護盾層數 | 絕對值(檢查事件數,與傷害量無關) | — |

### ⭐ 為何必須拆成兩個值(v3.0.1 修正)

若「能否通過」只由 `estimatedAverageHit × 3` 單一值決定,玩家平均單擊變強時門檻同步上升,**成長感被完全抵消**。

正確結構:

- **行為分類門檻**(依玩家構築)——判定「這一擊是否屬於重擊」。高單擊構築更容易產生合格重擊
- **Boss 耐久門檻**(依 Boss 層數與類型)——判定「核心需要多少重擊值才破裂」。玩家變強仍會讓破裂速度提高

⚠️ **必須設上下限**,避免玩家構築反過來讓 Boss 無限縮放。相對門檻的目的是讓不同構築可比,**不是讓成長失去意義**。

## 5.6 ⭐ Boss 適性驗收:相對優勢,禁止職業硬剋

**已否決的驗收標準**:「每職業至少通過一種 P0 Boss,且無職業能輕鬆通過兩種」。

該標準會導向:遇到某 Boss 必須換職業 / 某輪選錯職業就卡死 / 掛機玩家因無法臨場換職業被懲罰 / **職業成為答案,而不是構築提供答案**——直接違反「沒有唯一最佳解」與「掛機不受懲罰」兩條契約。

### 正確驗收標準

1. 三職業使用**基礎配置**時,在不同 Boss 上有 **10~20% 效率差**
2. 加入**一件針對傳說或合適傭兵**後,弱勢職業也可穩定通過
3. 不允許任何職業在所有 Boss 上同時維持最佳效率
4. 不允許任何 Boss 只有單一職業或單一傳說能解

### ⭐ 合併效率上限(v3.0.1 新增)

職業差(10~20%)、針對性傳說(10~25%)與適性傭兵若全部疊加,可能累積成事實上的硬剋。因此追加總量上限:

> **任一 Boss 上,最佳與最差「可達成構築」的效率差不得超過 40%,且最差構築仍須能通過。**

此上限優先於前述各項個別範圍;衝突時削弱個別項目。

> 目標是促使玩家「調整構築」,而不是「後悔選錯職業」。

## 5.7 偏好而非免疫

**禁止**:免疫暴擊、免疫燃燒、免疫召喚物、禁止某職業技能、強制穿指定套裝。

**允許三種寫法**:

| 寫法 | 範例 |
|---|---|
| 偏好(有破法) | 燃燒效果降低 30%,但凍結後移除此抗性 |
| 暫時遞減(可重置) | 連續受同一技能攻擊後效果遞減,使用不同機制可重置 |
| 可破解規則 | 護盾降低範圍攻擊效果,但破壞兩個圖騰後護盾失效 |

**所有時間懲罰必須配破法**:圖騰加速倒數 → 擊破圖騰;蓄力完成扣時間 → 期間達門檻;熱度滿扣時間 → 凍結可重置熱度。

## 5.8 招牌規則:一句話可描述

每個 Boss 突出**一個主要機制**,最多一個次要機制。

| Boss | 主要機制 | 次要 |
|---|---|---|
| 鐵甲守門者 | 外殼需多段拆除,核心需單次重擊 | — |
| 熔爐巨像 | 累積熱度,燃燒加速累積,**凍結可重置** | 熱度滿時剩餘時間 -15% |
| 時鐘祭司 | 週期加速倒數,達成傷害門檻可進入弱點期 | — |

> 熔爐巨像是設計範本:主要機制自帶破法,破法對應具體構築,失敗時玩家知道該補什麼。

玩家應能說「這隻要多段」「這隻要存爆發」,而不是「這隻血比較厚」。

## 5.9 戰前揭露:構築評估面板


### 可自動計算,不需逐隻手寫 ⭐

Boss 的「偏好機制」以 17 個關鍵字表述;玩家構築的關鍵字組成已存在於裝備 `mechanicTags` + 傭兵 + 命運刻印。

**但不可只比對標籤有無**(v3.0.2 修正)。否則會出現:一件很弱的燃燒裝也算具備 `status`;三種高頻分身也只顯示一個 `clone`;同樣有 `store` 但儲存量與釋放頻率可能天差地遠——面板顯示「多段:高」而實戰拆不動護盾。

聚合資料必須包含實質權重:

```ts
interface MechanicProfile {
  tag: MechanicTag;
  sourceCount: number;           // 來源數量
  expectedFrequency: number;     // 預估觸發頻率
  expectedContribution: number;  // 預估機制貢獻
  bossEfficiency?: number;       // 對當前 Boss 的效率
}
```

星等由「是否具備 + 來源數量 + 觸發頻率 + 機制貢獻」計算。**P0-B 前補上即可。**

與裝備頁「目前構築摘要」使用**同一份聚合資料**。

- 失敗原因餵給小兵列傳,讓死因具體化:「未能擊破熔爐巨像的外殼」

## 5.11 普通敵人的最小差異

每隻只需**一個可見行為**。這也補上 10~30 秒期待層。

| 敵人 | 行為 | 依賴 |
|---|---|---|
| **盾兵** | 前幾次攻擊效果降低,多段較易突破 | 無(P0) |
| **幽影** | 週期短暫消失,持續傷害可保留效果 | 無(P0) |

| 分裂蟲 | 擊敗後產生兩個小型目標 | 多目標 |
| 法師 | 存活一段時間後加速倒數 | 目標選擇 |
| 旗手 | 存在時提高其他敵人耐久 | 多目標 |

> P0 先做盾兵 + 幽影:零依賴,且分別預告了兩種 P0 Boss 機制,有教學價值。

# 第六章 傭兵

## 6.1 定位(光環定位已作廢)

> **傭兵 = 低頻率、高辨識度的戰鬥事件來源。**

光環等於穿了角色外皮的被動數值,玩家永遠不會說「剛剛那隻做了什麼」。

**待機 + 招牌行為模式**:

```
平時站主角後側 → 每 8~15 秒發動招牌行為 → 短暫進入焦點 → 退回次要位置
```

好的傭兵讓玩家說「剛剛盜賊跑去背刺了」,而不是「我好像多了 8% 傷害」。

## 6.2 護欄(數字化)

| 規則 | 值 |
|---|---|
| 傭兵總傷害占比 | ≤ 15% |
| 招牌行為間隔 | 8~15 秒 |
| 平時普攻 | 無(待機動畫) |
| 同時攜帶 | 1 隻 |
| 觸發召喚類事件 | 禁止(避免循環) |
| 納入平衡 | 見下方預算拆分 |

### ⭐ 預算拆分(v3.0.1 修正)

傭兵是獨立解鎖與養成內容,不是單件傳說。若整體 power-neutral,會出現「帶傭兵後本體傷害被扣除」「解鎖傭兵沒有實際變強」「升級只是重新分配傷害」。

| 層面 | 預算 |
|---|---|
| **傭兵槽本身** | 屬**角色成長預算**,可提供有限淨增益(同 § 3.7 第三層) |
| **傭兵之間的選擇** | **power-neutral**:同等級傭兵平均輸出與效益差 **±10% 內** |

> 換傭兵是「怎麼打」的選擇(盜賊偏標記背刺、工兵偏多段破盾、火術士偏狀態、冰法師偏延後碎裂),不是「有沒有帶就差很多」。行為適性可在對應 Boss 產生有限優勢,受 § 5.6 合併上限約束。

## 6.3 四行為原型

| 傭兵 | 類型 | 招牌行為 | 驗證 |
|---|---|---|---|
| 盜賊 | 位移型 | 消失 → 繞後背刺 → 留下破綻(可被主角消耗)→ 返回 | 位移、標記、**主角與傭兵互動** |
| 冰法師 | 控制型 | 凍結戰場,延後結算,解凍引爆 | 狀態、延遲、Boss 相容性 |
| 工兵 | 場地型 | 放置砲台,存在數秒週期攻擊 | 場地實體、週期攻擊、上限 |
| 火術士 | 狀態型 | 施加燃燒,疊滿爆燃 | 持續狀態、疊層、爆發視覺 |

## 6.4 非主角實體上限

| 類別 | 上限 |
|---|---|
| 常駐人形同伴(傭兵 + 常駐召喚物,存在 >5 秒) | **≤ 2**(傭兵佔 1) |
| 短時分身/殘影(≤5 秒) | ≤ 3 |
| 場地物件(軍旗、砲台、法陣) | ≤ 3 |
| 瞬時視覺事件(落雷、火焰、飛刀、範圍斬) | **不計入**,僅受效能上限 |

> 理由:clicker-ui 第一鐵則是「主角背影永遠是畫面焦點」,背後視角可用空間比側視窄。限制常駐人形,避免主角變成人群裡的一個。

## 6.5 取得與養成

- 取得管道分散:爬塔里程碑、轉生商店、特定 Boss 掉落、隱藏事件(非抽卡,適合 CrazyGames 無課環境)

  若必須給數值,僅限**非戰鬥屬性**(傭兵徽章獲得率、事件預覽),不得為任何可換算輸出的屬性
- 分頁:**併入英雄頁成為第五區**,不新增第七個分頁

# 第七章 傳承與轉生

## 7.1 傳家之器(統一命名,棄用「傳家寶」)

### 銘刻制:三個決策點

| 階段 | 決策 |
|---|---|
| **銘刻**(入口) | 玩家將任一部位的已鍛造裝備銘刻為傳家之器;**同時只能持有 1 件**,銘刻新的須先昇華舊的 |
| **餵養**(過程) | 每次轉生時三選一決定本輪成長方向 |
| **出口** | 三選一:**保留 / 昇華 / 封存**(見下) |

### 出口三選一(v3.0.2 修正 —— 解除死鎖)

v3.0.1 規定「銘刻新的須先昇華舊的」,但昇華又要求「完成修復後」。若玩家本輪不想修、無法修,或發現選錯,將長期無法更換。

| 選項 | 條件 | 結果 |
|---|---|---|
| **保留** | 隨時 | 繼續帶往下一輪 |
| **昇華** | **完成修復後** | 進入祭壇,獲得完整紀錄與祭壇共鳴 |
| **封存** | **隨時**(未修復亦可) | 騰出欄位,進入圖鑑,**但不提供祭壇共鳴** |

> 封存讓玩家能退出錯誤選擇,昇華仍保有「完成修復」的獨佔價值。

### 餵養路線(代價為機制型,非 HP)

| 路線 | 效果 | 代價 |
|---|---|---|
| 飲血 | 攻擊詞條成長 | 本輪金幣獲得 -15% |
| 聚財 | 金幣/掉寶詞條成長 | 本輪技能冷卻 +10% |
| 通靈 | 技能傷害/CDR 詞條成長 | 本輪素材掉落 -15% |

> ⚠️ 原「飲血 -10% HP」作廢——本作無玩家 HP。

### 保留機制,不保留強度

- 保留:傳說特性、套裝標籤、一條代表性詞綴
- 基礎數值隨輪次重新成長,避免開局碾壓
### ⚠️ 必定回歸(v3.0.1 關鍵修正)

v3.0 寫「基礎 50% 重現機率」,與 § 7.6「核心進度不可隨機消失」直接衝突。**一次「沒有回來」會破壞跨代信任**,這是傳承系統的存亡條件。

| 項目 | 規則 |
|---|---|
| 回歸 | **下一輪必定以殘缺形態回歸**,無機率判定 |
| 必定保留 | 傳說特性或核心機制 |
| 基礎數值 | 隨輪次重新成長(避免開局碾壓) |
| 隨機只影響 | 殘缺程度、額外詞綴、特殊變體 |
| 神匠傾向提升的是 | **修復品質與保留內容**——降低殘缺程度、保留第二條代表詞綴、使修復條件更易達成。**不是回歸機率** |

殘缺範例:殘缺版「暴擊**有部分機率**縮短冷卻」→ 完整版「每次暴擊都縮短,但每秒有上限」。

### 雙重期待(修正後)

1. **這一輪它會以什麼殘缺形態回來?**
2. **能不能在本輪完成修復,或產生昇華變體?**

> 不是「會不會回來」——那是隨機剝奪,不是期待。

## 7.2 傳家之器祭壇(昇華累積)

- **每件昇華物提供 8 點「祭壇共鳴」**(v3.0.2 修正:原「+8%」未定義加在哪裡,且會造成四種收益同時膨脹)
- 昇華時從非傷害方向中**選擇一項**投入:素材 / 鍛造 / 離線 / 探索
- 各方向的實際換算由 `game-balance` skill 定義,不在此寫死百分比
- 祭壇欄位初始 **6 格**,滿位後新昇華須替換舊件;可用勳章擴充至 10 格
- 完成度:每推進 100 層 +10%(**固定值,不做深層加速**——見 § 7.3 說明)

## 7.3 轉生收益(戰功勳章)

```
勳章效果:乘算計入 heroDPS,成本固定
```

⚠️ **禁止**:退回加法、對層數超線性(`(層數/10)^1.5` 等)。

**中期停滯的解法不走數值曲線**,改由內容寬度處理:
- 命運 × 職業組合的重玩動機(9 格矩陣)
- 拓寬型永久獎勵(圖鑑給可能性而非傷害)

### 成長乘區結構

| 乘區 | 來源 | 性質 |
|---|---|---|
| A | 戰功勳章 | 全局傷害、開局資金 |
| B | 傳家之器祭壇 | **非傷害向**:掉寶率、素材產出、離線效率 |

> 乘區 B 刻意設為非傷害向,避免與勳章重疊產生單一最佳解。

## 7.4 傳承總覽的三種心理功能

**① 證明沒有白玩 —— 顯示「本輪增加」而非只有總量**

```
本代帶來的永久變化
  勳章            +12
  鐵匠鋪經驗      +180
  新增圖鑑        2 件
  傳奇保底前進    +14%
  新增列傳角色    1 名
  首次解鎖        神匠系二轉
```

**② 預告下一輪快碰到什麼**(比回顧更重要)

```
再完成 1 次神匠命運 → 解鎖:傳家之器可保留第二條殘缺詞綴
圖鑑完成度 18 / 20  → 下一里程碑:傳承裝備出現率提升
```

每輪結束**至少給一個「已經快到了」的目標**。

**③ 歷代小兵列傳**

```
第七代・洛恩
重裝步兵 → 鐵壁工匠
神匠命運
抵達第 86 層
以「裂痕王盾」留下傳家之器
最終未能擊破熔爐巨像的外殼
```

⚠️ 結語不可寫「被打死」(無玩家 HP)。可用:未能突破 / 戰線潰散 / 時限耗盡 / 遠征止步於 / 未能阻止 Boss 完成儀式。

### 列傳擴充欄位

本輪代表構築、首次發現共鳴、特殊 Boss 擊破方式、本輪異變、最高連鎖或最高印記、傭兵代表事件。

> 讓每輪變成故事,而不是統計資料。

## 7.5 圖鑑

### 首版兩種(有回流作用者)

**① 傳承裝備圖鑑**(資料已在運作,成本最低)

顯示:首次出現於第幾代、最高品質、曾由哪位小兵持有、出現過哪些詞綴、是否曾成為傳家之器。

未收錄物**不顯示問號**,改用剪影 + 線索:「由重型盾牌在神匠命運下進化而來。」

**② 命運 × 職業矩陣圖鑑**(9 格)

| 一轉 | 神匠 | 尋寶獵人 | 戰術家 |
|---|---|---|---|
| 重裝步兵 | **鐵壁工匠** | 未知 | 未知 |
| 突擊斥候 | 未知 | 未知 | **影陣先鋒** |
| 隨軍法警 | 未知 | **遺物裁定者** | 未知 |

這張矩陣本身就是長期期待地圖,會自然產生「下一輪我想試試重裝步兵 + 戰術家」。

### 圖鑑獎勵:拓寬可能性,不加傷害

新事件加入事件池 / 新裝備變體加入產出池 / 開局可預覽一個額外命運節點 / 傳家之器多顯示一個可能結果 / 首次重鑄可免費鎖定一條詞綴 / 新外觀 / 新列傳稱號 / 新轉職候選。

> 原則:讓遊戲**越玩越寬**,而不是越玩數字越大。

## 7.6 隨機性的正確位置

### 固定獲得 + 隨機驚喜

轉生後**一定獲得**:勳章、圖鑑進度、鐵匠鋪經驗、一條列傳
**可能額外獲得**:傳家之器殘片、稀有列傳稱號、裝備異變、特殊旅途事件線索

> **核心進度不可隨機消失,隨機只負責讓結果偶爾超出預期。**

### 先給範圍,再揭曉

> 本代傳承評級預估:B ~ S
> 可能保留 1 ~ 2 項遺產

## 8.4 本輪異變(P2)

### ⭐ 兩層結構(v3.0.1 修正)

v3.0 的「每輪低機率出現異變」與心理契約五「每輪至少產生一個獨特事件」衝突——若異變是獨特事件的主要來源,就無法保證每輪都有。

| 層 | 機率 | 內容 |
|---|---|---|
| **本輪代表事件** | **必定產生** | 系統從本輪實際經歷中選出一項:首次完成某二轉 / 首次形成某構築 / 最高印記引爆 / 特殊 Boss 破解 / 傭兵代表行動 / 傳家之器修復 / **本輪最接近成功的失敗**。用於列傳 |
| **本輪異變** | 低機率 1~2 個 | 雙生傳說 / 特殊技能形態 / 傭兵強化事件 / 稀有 Boss 規則 / 特殊區域 / 傳家之器變體 |

> 「每輪都有故事」是確定的;「偶爾出現異變」是驚喜的。

限制:不影響必要永久進度、不形成唯一最佳解、不要求準時上線、可記錄進列傳。

# 第九章 期待循環與心理契約

## 9.1 五層期待循環(驗收用)

任何新功能上線前對照;若五層中有任一層是空的,該版本不會好玩。

| 時間尺度 | 玩家期待 | 對應系統 |
|---|---|---|
| 10~30 秒 | 下一次會出現什麼 | 護盾層數、弱點窗口、印記滿層、傭兵行為、普通敵人行為 |
| 2~5 分鐘 | 這輪流派開始成形 | 命運節點、施放策略、技能組合 |
| 10~20 分鐘 | 角色會轉成什麼 | 二轉逐步揭露 |
| 一輪結束 | 這代留下什麼 | 傳承結算、列傳、傳家之器 |
| 多輪累積 | 我的世界發生什麼改變 | 9 格矩陣、圖鑑、里程碑 |

## 9.2 六條心理契約(正式驗收規則)

違反者不得實作:

1. **掛機不受懲罰** —— 重要決策不因離線消失;限時事件只提供額外收益
2. **不同選擇必須產生不同戰鬥行為** —— 不可只是傷害/暴擊/冷卻的數值差
3. **重要結果必須可預測、可干預** —— 須具備預告 → 處理窗口 → 結果回饋;禁止無預告封鎖、完全隨機免疫、玩家無法改變的倒數懲罰
4. **重要機制必須可見、可聽、可敘述** —— 至少具備專屬圖形/音效/場地痕跡/獨立行動者/施放節奏/狀態圖示/連鎖結果之一
5. **每輪至少產生一個獨特事件** —— 由「本輪代表事件」機制**保證產生**(§ 8.4),不可依賴低機率異變
6. **失敗必須提供資訊或進度** —— 禁止只顯示「戰力不足,請繼續提升」

## 9.3 戰鬥心理循環

```
預告 → 玩家蓄勢 → 敵人開啟機制 → 施放策略生效
  → 狀態或裝備產生反應 → 接近成功或成功 → 顯示結果原因
```

範例:

```
[預告]  Boss:3 秒後核心開啟
        玩家:軍陣號令已就緒(策略=弱點開啟時施放)
              軍勢 8/10

[窗口]  核心開啟 4 秒
        單次重擊效果提高、儲存傷害釋放、戰意累積加倍

[結果]  成功 → 核心破裂,Boss 進入虛弱
        失敗 → 核心關閉;本次利用率 67%
```

技術:`tone` 或 Web Audio + 短樣本。音量三軌獨立可調 + 全靜音。

## 10.6 技能辨識演出(視為技能系統的一部分,非美術加分)

每個技能至少具備一項專屬辨識元素。各職業的視覺焦點:

- 重裝步兵看**陣位狀態**
- 突擊斥候看**破綻數與殘影**
- 隨軍法警看**法令順序**
- 神匠看**鍛印種類**
- 戰術家看**技能排列**

全部可用補間、縮放、透明度、拖影與粒子達成,**不需逐幀動畫**。

## 10.7 美術方向

- 風格:向量扁平/幾何風(可自產、具品牌識別度)
- 紙娃娃拆件:頭盔/披風/武器分層;**披風與武器在背面最顯眼**,轉職視覺差異優先投資此兩層
- 動畫策略:程式補間為主,不做逐幀
- 素材補充:Kenney.nl(CC0)、itch.io、AI 生成後手修

# 第十一章 技術架構

## 11.1 三層分離(不可違反)

```
/src
  /core      ← 純 TS 遊戲邏輯,零依賴,可獨立單元測試
  /ui        ← React 元件,只讀 store、發 action
  /render    ← Pixi 場景,只訂閱戰鬥狀態做演出
  /store     ← Zustand,core 與 ui/render 的橋樑
```

`/core` 不 import React/Pixi:換引擎、封 Capacitor、headless 平衡模擬都不需重寫。

## 11.2 關鍵依賴

| 套件 | 用途 | 備註 |
|---|---|---|
| `pixi.js` + `@pixi/react` | 戰鬥渲染 | — |
| `zustand` | 狀態管理 | 存檔 = store 快照 |
| `break_infinity.js` | **必裝**大數運算 | 所有 /core 數值一律 Decimal |
| `localforage` | IndexedDB 封裝 | 存檔含 version 欄位 + 遷移函式 |
| `tone` | 音效 | — |
| CrazyGames SDK | 廣告 + 雲存檔 | 對外測試前必須完成 |

## 11.3 工程注意事項

- 邏輯固定 tick(如 10/s),渲染走 requestAnimationFrame,兩者解耦
- 離線收益以 **timestamp 差值**結算(非 setInterval)
- 打包體積:spritesheet 合併、懶載入、tree-shaking(CrazyGames 初始載入 <5MB)
- 單元測試優先覆蓋 `/core`
- **兩套元件庫必須分離**:玩家側戰鬥事件庫(§ 4.1)vs 敵人側機制元件庫(§ 5.2),僅共用關鍵字

## 11.4 模擬器擴充(P0 必做)

現行 `balance-sim` 只跑「總 DPS vs Boss HP / 30 秒」。加入護盾、弱點窗口、施放策略後無法驗證平衡。

擴充項目:

1. **破盾值統計**(依 § 5.4)+ 反推每秒上限,使一般配置落在 50~60%
2. 最大單擊 / 平均單擊比值(驗證破甲門檻)
3. 弱點窗口內輸出占比(驗證施放策略效益)
4. **3 職業 × 2 種 P0 Boss × 有無施放策略**的效率矩陣

驗收依 § 5.6(相對優勢,非硬剋)。

# 附錄 A 機制關鍵字表(17 種)

**關鍵字 = 名詞**(UI 標籤與篩選);**事件 = 動詞**(程式執行單元)。

```ts
type MechanicTag =
  | 'clone' | 'status' | 'displace' | 'zone'          // v1.5 新增
  | 'repeat' | 'copy' | 'delay' | 'mark' | 'afterimage'
  | 'store' | 'transform' | 'chain' | 'spread'
  | 'cooldown_complete' | 'sequence' | 'relic' | 'formation';
```

| 關鍵字 | enum | 主要對應事件 |
|---|---|---|
| 分身 | `clone` | SpawnAlly / DespawnAlly |
| 狀態 | `status` | ApplyStatus / StackStatus / ConsumeStatus |
| 位移 | `displace` | MoveEntity |
| 區域 | `zone` | CreateZone |
| 重複 | `repeat` | RepeatAttack |
| 複製 | `copy` | RepeatAttack(讀取來源參數) |
| 延遲 | `delay` | DelayDamage / DeferDamageWindow / ReleaseDeferred |
| 標記 | `mark` | CreateMark / ConsumeMark |
| 殘影 | `afterimage` | SpawnAlly(短時)+ RepeatAttack |
| 儲存 | `store` | StoreDamage / ReleaseStoredDamage |
| 轉化 | `transform` | TransformStatus |
| 連鎖 | `chain` | ChainEvent |
| 擴散 | `spread` | CreateZone + ChainEvent |
| 冷卻完成 | `cooldown_complete` | AdvanceCooldown |
| 順序 | `sequence` | RecordSequence |
| 遺物 | `relic` | GrantRelic |
| 軍陣 | `formation` | CreateZone(重裝步兵特化子類,可被盾類技能互動) |

UI 要求:各關鍵字需有專屬圖示;稀有度不可只靠顏色(色弱可及性:傳說=菱形火焰、套裝=三角組合、傳家之器=家徽、鎖定=鎖頭)。篩選列須拆兩排:**詞綴篩選**(數值向)與 **機制關鍵字篩選**(機制向)。

# 附錄 B 設計限制清單(提案時必須遵守)

1. **遊戲沒有玩家 HP**。主角不會受傷或死亡,Boss 是限時 DPS 檢定。任何「扣血/殘血/吸血」設計都需先決定是否引入 HP 模型,那會改寫整個戰鬥底層
2. **命運樹節點是機制不是數值**。寫「攻擊 +5%」會讓唯一解問題重新出現
3. **流派間差距控制在 15~25%**;傳說/套裝 power-neutral,單件淨輸出 ±10% 內
4. **勳章加成必須乘算、固定成本**,不可退回加法,不可疊層數超線性
5. **重要分支只能放留存事件**(旅途紀錄),限時事件只給額外收益,否則懲罰掛機玩家
6. **所有檢定必須在配裝層可解**,不得要求執行層操作
7. **所有門檻採靜態預估相對值 + 上下限**,不用絕對值,不用戰鬥中即時採樣
8. **每個狀態至少要有一個非傭兵來源**(傭兵一次只帶 1 隻)
9. **MechanicTag 適用範圍**(v3.0.1 修正):所有影響**戰鬥行為、裝備構築與 Boss 判定**的效果須使用 MechanicTag,且不可寫純傷害百分比。
   **經濟、鍛造、傳承、事件密度與介面預覽等非戰鬥效果使用各自系統的型別**(如 `EconomyTag` / `ProgressionTag`),不強制套用戰鬥關鍵字——否則 MechanicTag 會逐漸變成包山包海的萬用分類
10. **重要資訊不得只靠音效**,必須有視覺冗餘
11. **玩家側事件庫與敵人側元件庫必須分離**
12. **系統級無限循環護欄**:重複與複製不得觸發自身(遞迴深度上限 1)、重複/殘影/複製 ≤3 次/秒、同關鍵字多來源疊加遞減(第 2 來源 70%、第 3 來源 50%、第 4 以後 30%)、任何技能實際冷卻不得低於基礎值 30%
13. **延遲行為必須明確歸類**(v3.0.1 修正):表現延遲不延後邏輯結算;機制延遲須定義 Boss 戰結束處理與窗口倍率結算時點(見 § 4.3)。**不得使用未定義的延遲行為**
