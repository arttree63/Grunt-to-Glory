# 第一章 遊戲定位與核心概念

- **遊戲名稱**:《小兵的故事》
- **類型定位**:點擊放置 RPG / 雜兵逆襲英雄之路(Clicker / Idle RPG)
- **目標平台**:Web/PWA → **CrazyGames 上架** → Capacitor 封包雙平台手遊(iOS/Android)
- **核心樂趣**:
  - 「無名雜兵 → 傳奇英雄」的成長與轉職視覺反差
  - 高自由度天賦配點與鐵匠鋪鍛造刷寶
  - 爽快無負擔的點擊/放置成長與轉生傳承機制
  - **主角永遠是戰鬥核心**(傭兵僅輔助,與點擊泰坦後期主角邊緣化做出區隔)

## 核心循環

```
[ 初始無名小兵 ] → [ 點擊 / 自動擊殺怪物 ] → [ 獲取金幣、經驗、素材 ]
        ▲                                          │
        │                                          ▼
[ 退役 / 傳承轉生 ] ← [ 極限爬塔撞牆 ] ← [ 升級配點 / 轉職 / 鍛造換裝 ]
 (保留傳家寶+戰功勳章)
```

1. **戰鬥與積累**:點擊或自動攻擊,擊敗怪物取得金幣、經驗與素材
2. **養成與分支**:分配屬性與天賦點數,達成條件多階轉職;素材至鐵匠鋪鍛造裝備
3. **驗證與瓶頸**:每 10 層限時 Boss,檢驗整體 DPS
4. **傳承與重啟**:爬塔極限後「退役/傳承」,資源轉為永久戰功勳章與傳家寶

# 第二章 主角戰鬥與養成

## 2.1 屬性配點(Talent Points)

每升一級獲得配點,自由分配:

| 屬性 | 效果 | 實作現況(2026-07-29) |
|---|---|---|
| 力量 STR | 基礎攻擊力、暴擊傷害 | ✅ 傷害 ×1.024/點、暴傷 +0.5%/點 |
| 敏捷 AGI | 攻擊速度、點擊收益、暴擊率 | ✅ 暴擊率 +0.5%/點、點擊戰意 +3%/點(無獨立攻速,本作為連續 DPS 模型) |
| 智力 INT | 技能傷害、技能冷卻縮短(CDR) | ✅ 技能傷害 +3%/點、CDR −0.5%/點(上限 −50%) |
| 幸運 LUK | **鍛造品質權重**、金幣掉率 | ✅ 品質升階 +0.2%/點、金幣 +1.5%/點 |

> ⚠️ **本節已作廢(2026-07-29)**:四維天賦實測力量是唯一解(40 點:力量 ×16.21、次佳 ×7.53),
> 已**整套移除**,由**命運樹(Destiny Tree)**取代。節點是機制不是數值,見附錄三。

## 2.2 轉職樹(Job Tree)

- **Tier 0(初始)**:無名小兵(揮砍木劍)
- **Tier 1(Lv.20)**:
  - 重裝步兵(防禦、反傷、盾擊)
  - 突擊斥候(攻速、暴擊、點擊收益)
  - 隨軍法警(主動技能、範圍 AOE)
- **Tier 2(Lv.100)**:聖騎士、影舞者、大元素使…
- **Tier 3(終極)**:傳奇英雄、弑神者…

> **實作現況**:Tier 0~2 已完成,共 7 個職業,分支固定(重裝步兵→聖騎士 / 突擊斥候→影舞者 / 隨軍法警→大元素使)。
> 每個職業帶**被動 + 主動技能**;技能分 buff 型與立即傷害型,後者是突破 Boss 限時檢定的工具。
> Tier 3 未實作。
- **紙娃娃換裝**:轉職與裝備切換同步更新角色外觀與攻擊特效
  - 美術實作:角色拆 頭/身/武器/特效 四層 sprite,換裝即換圖層

## 2.3 主角為核心的戰鬥設計(重要)

- **點擊強化自動攻擊,不分開計算**:主動點擊為主角疊「戰意」buff(攻速/傷害暫時提升);放置時仍是主角在打,只是節奏慢。點擊永遠有感,同時保留掛機性
- 所有主動技能綁定主角(由轉職決定技能組)
- 視覺上傷害永遠來自主角,傭兵站側後方做輔助演出

# 第三章 傭兵系統(輔助定位)

## 3.1 設計原則

- **一次只能攜帶一隻**,但可收集多隻 → 主角保持焦點,收集慾撐長期目標
- 傭兵**不直接輸出**(或傷害占比 <10%),定位為光環 buff + 特殊機制
- 切換傭兵 = 切換策略(推塔/刷金/掛機/收集),而非數值高低之分
- 不做傭兵隊伍、不給傭兵裝備欄,避免失焦

## 3.2 傭兵範例(初版 4~6 隻)

| 傭兵 | 光環 | 特色機制 |
|---|---|---|
| 軍旗手 | 攻擊 +% | 戰意 buff 持續時間延長 |
| 隨軍牧師 | CDR | Boss 戰死亡可復活一次 |
| 軍需官 | 金幣/鍛造品質提升 | 寶箱怪出現率提升 |
| 老獵犬 | 暴擊率 | 自動拾取素材 |
| 吟遊詩人 | 經驗 +% | 離線收益時間上限延長 |
| 逃兵新手 | 無光環 | 搞笑彩蛋型,偶爾撿到奇怪垃圾(彩蛋裝備池) |

## 3.3 取得與養成

- **取得管道分散**(非抽卡,適合 CrazyGames 無課環境):爬塔里程碑、轉生商店、特定 Boss 掉落、隱藏事件
- **養成輕量**:消耗「傭兵徽章」升級光環數值
- 圖鑑收集給全隊微量屬性加成(與英雄榜圖鑑整合)

## 3.4 美術成本

傭兵只需待機動畫 + 1~2 個小動作(舉旗、唸咒、搖尾巴),單隻成本約主角 1/5。剪影辨識度做足(高矮胖瘦、人/動物/怪物混搭)。

# 第四章 裝備與鍛造系統

## 4.1 設計核心

**怪物不掉裝備,掉素材;裝備一律由鐵匠鋪鍛造產出。**

- 合併掉落制與抽獎制優點:打怪有積累感,開錘有開箱期待感
- 素材名稱即規則,零教學成本
- 裝備可分解回素材,經濟閉環、無垃圾裝

## 4.2 素材體系(3 類)

| 素材 | 來源 | 鍛造效果 |
|---|---|---|
| **怪物素材** | 所有怪物 100% 掉落 | 隨機部位、隨機品質 |
| **部位素材**(頭/身/武器/鞋/飾品) | 每 10 層 Boss 掉落 | 鎖定部位,品質隨機 |
| **菁英素材** | 稀有掉落 | 品質下限保證:菁英(紫)以上 |

### 菁英素材來源(掉率抓緊,經濟中最貴資源)
1. 寶箱怪/黃金哥布林小機率掉落
2. 轉生商店少量兌換(戰功勳章)
3. 每日首殺 Boss 保底 1 個(留存鉤子)

### Boss 部位素材輪替表

| 層數尾數 | 掉落部位 |
|---|---|
| X10 | 頭部素材 |
| X20 | 武器素材 |
| X30 | 身體素材 |
| X40 | 鞋子素材 |
| X50 | 飾品素材 |

(循環;層數越高附帶品質權重越好)

**❌ 不設傳奇素材**:菁英素材是唯一保底券,避免保證階級通膨。傳奇/神器靠機率 + 保底計數,保留驚喜。後期版本可加「神匠結晶」作終局內容。

## 4.3 鐵匠鋪(鍛造介面)

### NPC 包裝
「怪物分解商 + 鐵匠」為同一組戰場後勤搭檔。(彩蛋伏筆:未來可成為傭兵候選)

### 鍛造模式(僅 2 種,3 秒看懂)

| 模式 | 消耗 | 產出 |
|---|---|---|
| **普通鍛造** | 怪物素材 ×10 | 隨機部位、隨機品質 |
| **精工鍛造** | 怪物素材 ×10 + 部位素材(可選)+ 菁英素材(可選) | 依素材鎖定部位/品質下限 |

### 所見即所得預覽
- 怪物素材 → 「將獲得:隨機裝備」
- + 頭部素材 → 「將獲得:隨機頭盔」
- + 菁英素材 → 「將獲得:隨機頭盔(菁英以上)」

### 品質機率修正
- LUK 屬性、軍需官傭兵光環、鐵匠鋪等級(累積鍛造次數升級)

### 保底機制
- 精工鍛造累計 50 次未出傳奇(金)→ 下次必出傳奇以上(計數器可見)

### 體驗要求
- 開錘動畫要爽(核心開箱時刻):舉錘 → 火花 → 品質光效
- 必須支援跳過 / 十連鍛;十連結果清單展示,最高品質置頂

## 4.4 裝備規格

- **部位**:武器、頭盔、鎧甲、鞋子、飾品(5 格)
- **品質**:白 → 綠 → 藍 → 紫(菁英)→ 金(傳奇)→ 暗紅(神器)
- **隨機詞條**:+X% 點擊傷害、金幣掉率、技能冷卻、暴擊率等
- **套裝效果**:Phase 2 後加入(如「老兵套裝」3 件全傷害 +50%)
- **傳家寶**:轉生時指定 N 件保留至下一代
- **分解回收**:依品質階梯返還怪物素材;支援「一鍵分解 X 品質以下」

## 4.5 循環總圖

```
打怪 ──→ 怪物素材(積累)
Boss ──→ 部位素材(定向)
事件 ──→ 菁英素材(保底券)
              │
              ▼
         鐵匠鋪鍛造 ──→ 裝備 ──→ 變強 ──→ 爬更高
              ▲                │
              └── 分解回收 ◄────┘
```

**動機綁定**:想畢業神裝 → 需特定部位素材 → 打對應層 Boss → 爬塔與刷寶動機合一。

# 第五章 傳承/退役機制(Prestige)

- **敘事包裝**:小兵達極限層數後功成名就退役(或戰死),下一代接棒
- **戰功勳章(聲望貨幣)**:依最高層數發放,解鎖全局永久科技:
  - 初始開局資金
  - 全局傷害加成
  - 傭兵徽章 / 菁英素材兌換
- **傳家寶**:指定 N 件神裝保留,加速開局

> **實作現況**:勳章是**純貨幣、無被動加成**,效果全來自五條可購買科技,每級**乘算**:
> 軍功勳令(傷害 ×1.10)/ 後勤補給(金幣 ×1.12)/ 老兵餘蔭(開局資金 ×5)/
> 家族傳承(+1 件傳家寶)/ 營地帳篷(離線上限 +2h)。
>
> ⚠️ **關鍵約束**:加成必須「每級乘算 + 固定成本」。舊版「每枚 +5% 傷害」是加法,
> 而怪物 HP 對層數是指數,線性加成必然造成中期同層停滯(實測 121→121)。
> **改成乘算後停滯已消除**,任何新方案都不要退回加法,也不要再疊「勳章對層數超線性」——
> 實測兩者疊加會失控(第 5 輪科技暴衝到傷害 ×34)。
- **英雄榜/圖鑑**:收集過的職業、裝備、傭兵入圖鑑,提供微幅全隊加成

# 第八章 技術架構

## 8.1 技術總覽

| 層 | 技術 | 職責 |
|---|---|---|
| UI 層 | React 18 + Zustand | 所有介面(佔開發量 ~80%) |
| 渲染層 | Pixi.js(`@pixi/react`) | 戰鬥畫面、sprite、特效、傷害跳字 |
| 邏輯層 | 純 TypeScript 模組 | 數值、掉落、鍛造、離線收益、存檔 |
| 儲存 | IndexedDB(localforage) | 本地存檔 |
| 發布 | Web/PWA → CrazyGames → Capacitor | 三階段 |

## 8.2 三層分離原則(重要)

```
/src
  /core      ← 純 TS 遊戲邏輯,零依賴,可獨立單元測試
  /ui        ← React 元件,只讀 store、發 action
  /render    ← Pixi 場景,只訂閱戰鬥狀態做演出
  /store     ← Zustand,core 與 ui/render 的橋樑
```

- `/core` 不 import React/Pixi:換引擎、封 Capacitor、headless 平衡模擬都不需重寫
- 所有數值公式集中 `/core/formulas.ts`

## 8.3 關鍵依賴

| 套件 | 用途 | 備註 |
|---|---|---|
| `pixi.js` | 戰鬥渲染 | ⚠️ **未採用 `@pixi/react`**(v8 需 React 19),改用純 pixi 掛在 React 容器 |
| `zustand` | 狀態管理 | 存檔 = store 快照 |
| `break_infinity.js` | **必裝**大數運算 | idle 後期超過 Number 上限;/core 數值一律 Decimal |
| `localforage` | IndexedDB 封裝 | 存檔含版本欄位 |
| Pixi Ticker / `@tweenjs/tween.js` | 補間動畫 | 打擊感 |
| CrazyGames SDK(npm) | 廣告+雲存檔 | Phase 2 前接入 |

### 參考開源
GitHub 搜 `idle-game react` / `incremental game typescript`,重點研究:
1. Game loop 與渲染幀率解耦
2. **離線收益以 timestamp 差值結算**(idle 遊戲最常見錯誤來源)

## 8.4 AI 開發工具分工

| 工具 | 角色 | 適用任務 |
|---|---|---|
| **Claude Code** | 主力 | 架構、/core 邏輯、多檔重構、長期迭代 |
| **Codex** | 輔助 | 明確規格單點零件:工具腳本、UI 元件量產、資料表轉換 |

## 8.5 自建 Skill 規劃(Claude Code 用)

1. **`clicker-ui`**:直向佈局(上戰鬥/下技能列+tab)、底部 Tab(英雄/裝備/鐵匠鋪/傭兵/商店)、數值縮寫(1.2K/3.4M/…)、彈窗與紅點慣例
2. **`game-balance`**:成長曲線、Boss DPS check、轉生收益、鍛造消耗與掉落期望公式——數值唯一真相來源,調整必同步更新
3. **`project-handoff`**(已存在):session 結束產出 handoff.md,新 session 自動載入

## 8.6 工程注意事項

- 所有遊戲數值用 Decimal(break_infinity),含存檔序列化
- 存檔帶 `version` 欄位 + 遷移函式
- 邏輯固定 tick(如 10/s),渲染走 requestAnimationFrame,兩者解耦
- 離線收益上限做成設定值(吟遊詩人傭兵會修改)
- 打包體積監控:spritesheet 合併、懶載入、Pixi tree-shaking(CrazyGames 審核:初始載入 <5MB)
- 單元測試優先覆蓋 /core

# 第十章 開發路線圖

## 目前最大的三個設計困境

1. **開錘變異壓過轉生成長**:裝備乘區 ×3.2~×12.2,轉生科技只有 ×1.2~×3.5,輪次表現主要看開錘手氣。降低變異會犧牲開箱樂趣,兩者衝突。
2. **天賦是假選擇**:力量收益是次佳的 2.2 倍,沒有理由不全點力量。
3. **玩家看不出自己變強**:裝備完全不影響角色外觀,渲染層沒有讀裝備資料。這是企劃第一條核心樂趣。

## 驗證能力的邊界(提案時請納入考量)

- 所有平衡結論來自 headless 模擬(`npm run sim`),模擬直接驅動真實遊戲迴圈,不會與遊戲漂移
- 但**模擬裡的「玩家」是寫死的策略**(全點力量、有素材就開錘、比身上好就換),真人不會這樣玩
- **連「玩家何時會放棄轉生」都是設定值**(一個 10 層區塊超過 12 分鐘),沒有真人驗證
- 模擬能驗曲線,**不能驗手感**
- ⚠️ **遊戲沒有玩家 HP 系統**:主角不會受傷或死亡,Boss 是限時 DPS 檢定。
  任何以「扣血/殘血/吸血」為代價或機制的設計,都需要先決定是否引入 HP 模型(那會動到整個戰鬥設計)

# 附錄三:命運樹 MVP(2026-07-29 決議,取代第二章 2.1 天賦配點)

## 為什麼換掉天賦

四個屬性都在同一把尺上比大小 → 必然有唯一解。命運樹的節點是**機制**,機制之間沒有共同尺度。

## 首版範圍(刻意做小)

驗證四件事,不以內容量為目標:玩家看到節點會不會猶豫、選擇會不會改變接下來幾分鐘的行為、
會不會期待下一個節點、轉生後願不願意為另一條路再玩一輪。**這四件不成立,做五十個節點也沒意義。**

- **神匠**(打造流,接現有鍛造):起始 + 兩次二選一 + 終局二選一 = 7 個節點
- **尋寶獵人**(事件流,接現有突發事件):同上 7 個節點
- **戰術家**(連斬流):只做 3 個節點,作為純戰鬥對照組,用來檢驗玩家是否真的依玩法偏好選擇,
  而不是一律選收益最高的經濟流

單輪玩家只會拿到 4 個節點(起始 + 3 次決策),所以重玩性來自「這輪走哪條」。

## 已定的關鍵決策

1. **首版不引入玩家 HP**。引入 HP 不是加一個數值,而是改寫整個戰鬥模型(怪物如何攻擊、
   死亡懲罰、掛機期間死亡、Boss 還是不是純限時檢定)。原「狂戰士:越殘血越強」延後,
   改以連斬流作為戰鬥型代表。**命運樹只能重新組合現有系統,不能要求新增戰鬥底層。**
2. **傳家寶銘刻併入神匠流派**,不做獨立核心系統,避免又變成「系統很多但不知道為什麼存在」。
3. **命運點可離線累積,決策不暫停推進**。上限 2 枚,滿了停發但遊戲照跑。
4. **重大分支只放留存事件**(旅途紀錄),限時事件只提供額外收益,否則會天然懲罰掛機玩家。
5. **舊天賦全額返還,不自動替玩家選流派**——那等於上線第一刻就替玩家做掉最重要的選擇。

## 首版不做

玩家 HP、隨機生成整棵樹、黑化與污染、大量隱藏職業、跨職業混搭、五條完整流派、
命運共鳴、每輪節點排列不同。這些都建立在「基本選擇已經好玩」的前提上,還沒驗證。
