# 《小兵的故事》Clicker UI 規範 v1.0

> 定案依據:背後視角構圖原型(已驗收)。任何視覺調整需先更新本 skill 再實作。

## 一、核心構圖(背後視角)

直向手機佈局,由上而下:

```
┌─────────────────────┐
│ 頂欄:層數(左)/金幣(右)  │  漸層遮罩,不擋畫面
│ [Boss 層:名稱+血條+倒數] │  僅 Boss 戰顯示
│                     │
│    怪物由深處湧來      │  小徑梯形透視,遠小近大
│         ⇣           │
│                     │
│      主角背影         │  下方中央,佔屏高 1/4~1/3
│   傭兵(側後方一格)     │
│   [戰意條(主角腳下)]   │
├─────────────────────┤
│ 技能列(4 格)          │
│ Tab:英雄/裝備/鐵匠鋪/  │
│     命運/旅途/傳承      │
└─────────────────────┘
```

### 不可違反的構圖原則
1. **主角背影永遠是畫面焦點**:位於底部中央,任何 UI 不得遮擋
2. 視線動線:怪物(上)→ 主角背影(中下)→ 操作區(底)
3. 怪物「眼睛面向玩家」,製造對峙感
4. Boss 軀體**刻意超出畫面左右邊界**、位於上半屏俯壓,巨眼俯視玩家
5. 傭兵站主角左側後方一格,只做待機動畫,不得搶焦點

## 二、主角紙娃娃(背面分層)

由下至上圖層:戰意光環 → 披風 → 軀幹 → 頭+盔 → 右臂+武器(armPivot)

- **披風與武器是背面最顯眼的換裝件**,轉職視覺差異優先投資在這兩層
- 揮砍 = 只旋轉 armPivot 層(0.5 → -1.5 rad 回彈),身體不動
- 待機:身體 Y 軸 sin 呼吸(±3px)

## 三、深度感公式(偽 3D,不用真 3D)

怪物生命週期參數 `t`(0=深處出生 → 1=近戰位):

```
ease = t²                        // 越近越快
y  = H * (0.44 + 0.27 * ease)
x  = W * (0.5 + offset * (0.3 + 0.7 * ease))   // offset ∈ ±0.13
scale = (0.25 + 0.95 * ease) * min(W,H)/420
zIndex = y                        // Y 軸排序
alpha = min(1, t * 6)             // 出生淡入
```

一般層同屏怪物上限 4 隻,間隔 450~950ms 生成。

> v1.1 調整(實機截圖檢出):原本 y 係數 0.30 + offset ±0.08,怪走到近戰位會壓在主角頭盔上、且全擠中線,違反「主角是焦點」原則 → 近戰位上移一點並加大橫向散開。
> 生成間隔由 900~1600ms 縮短:實際遊戲的擊殺速度遠快於原型(原型是手動點擊),間隔太長會讓畫面常態空無一物、打擊沒有對象。

| 傷害跳字 | 普通 24px 白字/暴擊 34px 金字 `#ffd23e`,黑描邊 5px,上飄+重力回落,900ms 淡出 |

## 五、戰意系統(點擊 = 直接出手 + 強化自動攻擊)

- **每次點擊直接出一次手**:一次點擊 = 一次揮砍 = 一次傷害跳字 = 一次扣血(1:1,不會有空點)
- 每次點擊 +7 戰意,自然衰減 0.008/ms,上限 100
- >30 時主角腳下出現青色橢圓光環(呼吸半徑 70±6px)
- 滿 100:揮砍軌跡變色(未來:攻速/傷害 buff 生效視覺)
- UI:主角腳下 150px 細條,標籤「戰 意」字距 4px

## 七之二、英雄頁四區呈現(v1.3)

玩家抱怨「技能太少」有一半是介面造成的——所有東西混在一個清單只看到兩顆按鈕。
英雄頁**必須依來源分區**,不可混成一列:

```
主動技能    4     ← 有施放與冷卻
戰鬥法則    2     ← 職業核心被動(規則型)
命運刻印    3     ← 來自命運樹的機制
已啟動共鳴  1     ← 達成組合後的質變效果
```

一輪結束時玩家可能持有十個以上被動,分區是可讀性的前提。

**已實作**(`HeroPanel` 的 `AbilitySections`),四區為:主動技能(含實際冷卻)/ 戰鬥法則(職業被動)/
命運刻印(節點說明)/ 裝備機制(傳說 + 套裝)。空的那一區要寫出**怎麼拿到**,不要留白。

⚠️ 這一區是「玩家唯一能查自己有什麼能力」的地方。技能說明**不可以只放在技能列的 `title`**——
手機沒有 hover,等於不存在。

## 七之三、技能辨識元素(v1.3)

每個技能至少要有一項可辨識元素(特定圖形 / 音效 / 場地痕跡 / 狀態圖示 /
施放節奏 / 連鎖結果),避免「八招技能但全自動施放、只看到特效亂飛」。

各職業玩家實際在看的東西:

| 職業 / 命運 | 看什麼 |
|---|---|
| 重裝步兵 | 護陣位置 |
| 突擊斥候 | 破綻數與殘影 |
| 隨軍法警 | 元素順序 |
| 神匠 | 鍛印種類 |
| 戰術家 | 技能排列 |

⚠️ 上表多數項目**需要戰鬥模型支援位置與多目標**,現行模型不具備,見 game-balance skill 的前提缺口一節。

## 七之四、裝備與鍛造結果呈現(v1.4 裝備分層)⭐

**資訊優先序,字級與位置必須反映它**:

```
傳說特性 / 套裝效果 → 機制關鍵字標籤 → 關鍵詞綴 → 基礎數值 → 一般附加屬性
```

### 機制差異優先於戰力 %

換裝比較固定三段,**機制得失放在數值之上**:

```
── 與目前裝備比較 ──
將失去 「技能持續」
將獲得 傳說特性「不退之壁」
將獲得 陣地基底(技能持續長、冷卻略慢)
開啟新構築
```

⚠️ 只顯示綠箭頭的話,整套構築設計會退化成「數字大的就穿」。

### 傳說與神器不顯示戰力 %

它們是 power-neutral 的(淨輸出 ±10%),戰力差幾乎都落在雜訊裡,
顯示數字只會把玩家推回綠箭頭思維。改顯示**構築關係**:

| 值 | 何時 |
|---|---|
| 契合目前構築 | 與身上其他傳說的機制關鍵字有交集 |
| 開啟新構築 | 引入目前沒有的機制 |
| 與目前構築衝突 | 會取代掉正在運作的傳說 |

白 / 綠 / 藍 / 紫**照常顯示戰力 %**——那裡的戰力才是真實決策依據。
程式端 `compareEquipment()` 對傳說回傳 `powerDelta: undefined`,UI 不需要自己判斷。

### 傳說卡片必備四行

1. 核心特性(它怎麼改變技能,不是攻擊力)
2. 標籤 = 機制關鍵字 + 影響技能
3. 適合構築
4. **不可重鑄**(否則玩家以為能洗掉,拿到不合用的詞綴會產生挫折)

### 套裝標籤呈現

標籤制:名稱後綴 `[帝國鐵壁]`,不是稀有度階級。卡片必須同時顯示:

```
[帝國鐵壁] 已裝備 2/3
2 件 持續型技能施放時同時展開軍陣,軍陣期間攻擊間隔縮短
3 件 軍陣結束時,把視窗內累積的印記自動引爆一次   ← 未啟動,淡色
還需任意 1 件帶「帝國鐵壁」標籤的裝備
```

⚠️ **未啟動的效果一定要顯示**(淡色/鎖定樣式),只拿到一件的玩家才知道值得繼續蒐集。
鍛造結果頁顯示的是「**換上後**會湊到幾件」,背包頁顯示「目前已裝備幾件」。

### 白裝與打造入口

白裝不列大量說明,只強調它是什麼基底(快速 / 重擊 / 陣地 / 技能)與可打造方向。
精工鍛造投入菁英素材時可**指定基底**,鍛造頁要寫出每個基底通向哪一系。

### 十連鍛造排序

帶傳說特性者置頂,其次才依品質——玩家要先看到「會改變玩法的那一件」。

## 七之五、事件-演出對照與狀態可見性(v1.5 審查後定案)⭐

### 演出資料一律走事件或 snapshot,render 不 import 遊戲邏輯

需要新資訊時,是往 `GameEvent` 加欄位或往 `BattleSnapshot` 加狀態,
**不是**讓 `BattleScene` 去讀 core 的函式。目前契約:

- `skill` 事件帶 `skillId` / `damage` / `count`(消耗的印記層數)
- `cooldownAdvance` 事件帶 `skillId` / `seconds`
- snapshot 帶 `buffSkill` / `buffPermanent` / `buffLeft` / `sigils` / `sigilMax` / `combo` /
  `charging` / `chargeStacks` / `relicLeft` / `bannerStored` / `commandReady` / `legends` / `bossTimeLeft`

### 事件必須有演出,或明示豁免

`GameEvent` 的**每一個型別**都要在演出層有對應,或在這裡寫明豁免理由。
一次審查抓到 20 個型別有 10 個沒有任何監聽者——技能直傷(全遊戲最大的一擊)就是其中之一。

| 事件 | 演出 |
|---|---|
| attack / moraleBurst | 揮砍 + 跳字 |
| **skill** | 大金字 + 震屏(事件帶 `damage`) |
| kill / bossKill / bossFail | 金幣跳字 / 擊破大字 / 撤退 |
| eventKill / eventEscape / clickMaterial | 事件獎勵 / 逃走 / **素材 +1(獨立模板)** |
| destinyPoint / partDrop / heirloomRestored / bannerStore | 一行 notice |
| levelUp | 豁免:HeroPanel 內已有即時回饋 |
| eliteDrop / weaponEvolve / encounter / floorUp / runReset | floorUp 走行軍衝刺;其餘待補 |

### 狀態可見性鐵律

任何**影響 DPS 或改變技能行為**的暫時狀態,「觸發條件 → 生效中 → 結束」三段都要看得見:
軍旗儲存量、遺物弱點倒數、常駐軍陣、指揮形態、印記層數、連斬、蓄勢、傳家之器修復進度。
看不見的機制等於不存在,玩家會以為裝備壞了。

### 戰場狀態兩層制(2026-07-31 取代固定槽位堆疊)

狀態一多,固定槽位(46/74/102…)會把主角圍在文字卡裡。改為兩層:

1. **主要機制卡**(同時只有一張,`bottom: 214`):完美引爆窗口 > 蓄力打斷 > 圖騰 > 護盾,
   依此優先序擇一顯示,帶 goal-bar。聚光燈教學的 `.spotlit` 掛在這張卡上。
2. **狀態 chip 列**(`bottom: 74`,單行):buff、印記、連斬、遺物、軍旗、蓄勢、乘勝等
   全部收成小 chip;超過 3 個折成「+N」,點擊展開。
⚠️ 禁止再用固定槽位往上堆新狀態行;新狀態一律加進 chip 列或競爭主要機制卡。

### 底部安全區(iPhone Home Indicator)

`.bottom` 的 padding-bottom 與高度必須含 `env(safe-area-inset-bottom)`;
所有算高用 `calc(var(--bottom-h) + env(safe-area-inset-bottom))`,不可寫死。
Tab 文字保持兩字(鐵匠鋪在 tab 顯示為「鍛造」,面板標題不變)。

### 常駐 buff 顯示「常駐中」

`Infinity` 禁止進 `toFixed`(不退之壁曾顯示「生效中 Infinitys」)。

### 跳字節流規格

普通 160ms、**暴擊 100ms**(不是不節流:點擊改為直接出手後跳字量翻倍,不節流會把同屏 12 上限洗掉其他字)、
金幣 220ms、素材獨立模板。錯開位置 5 格。
**沒有怪在畫面上時要 fallback 到路徑中央**,不可讓整組回饋消失(剛清屏那幾百毫秒會變成「點了沒反應」)。

### 破壞性操作

- 一鍵分解**必須排除**傳家之器 / 傳說特性 / 套裝標籤件(殘缺版傳奇會降成稀有,舊版會直接銷毀玩家唯一的傳承)
- 傳說 / 套裝 / 傳家之器單件分解要二次確認,用遊戲內 modal,**禁用原生 `confirm()`**
- 不可逆操作要有結果回饋(分解幾件、返還多少、保留了幾件)

### 觸控與字級

- 互動目標最小 **44px**(手機上「裝備」與「分解」擠在一起會誤觸)
- **禁止把 `title` 當唯一說明載體**(手機沒有 hover)
- 字級下限 11px;卡片內三級字階對應 § 七之四 的資訊優先序

### 面板選項跨開合保留

鍛造模式 / 部位 / 菁英 / 基底切 tab 不歸零——每輪重選四次是純粹的重複勞動。

### 前進感

Boss 戰與突發事件期間地面流線**停止**(那是停下來處理的事);進層衝刺的可感知時長 ≥0.5s;
腳邊塵土比遠景流線更能被感知,兩者都要有。

### 教學與情境提示

開局說明只講**現在就會用到**的事(點擊攻擊、金幣升級),其餘改成**情境觸發**:
第一次進 Boss 層、素材第一次夠鍛造、第一次拿到命運點、第一次累積印記、第一次拿到傳說或套裝件。
⚠️ 一次倒四張的說明,第 3、4 張講的是 3~10 分鐘後才碰到的東西,新手記不住。
提示存 localStorage,不佔存檔。

### 總攻的儀式感(v1.6)

- 兩招以上**全部轉好**時技能列整排金光呼吸(`.skills.all-ready`)——提示玩家「留著一起放」
- 多槽 buff 的狀態文字**併成一行**(「盾牆突擊 8.2s・不動如山 12.1s」),總攻疊窗不佔多個槽位
- 戰意昂揚每層跳一行 notice(+N%);乘勝推進走狀態槽位頂部

## 八、數值顯示格式

- 縮寫階梯:1.2K → 3.4M → 5.6B → 7.8T → 之後 aa, ab, ac…(定義於 `/core/format.ts`,UI 不得自行實作)
- 等寬數字:倒數計時、金幣使用 `font-variant-numeric: tabular-nums`
- Boss 倒數:18px 粗體置中,剩 <5 秒變紅

## 九、互動慣例

- 點擊攻擊區 = 整個戰鬥畫面(stage),不是按鈕。點擊會直接造成傷害,不是只餵戰意
- 跳字錯開位置為 5 格(點擊改為直接出手後跳字量幾乎翻倍,3 格會疊成一團)
- 升級按鈕支援**長按連點**(150ms 間隔加速)
- 一切彈窗可點外部關閉;鍛造結果十連以清單展示、最高品質置頂
- 禁用 `<form>`;所有互動用 pointer 事件(支援觸控)

## 十、技術約束

- Pixi 層只訂閱戰鬥狀態演出;HTML/React 層負責所有面板 UI(兩層不互相 import)
- 震屏/zoom 作用於 `world` container,UI 層(HTML)不受影響
- resizeTo 容器、max-width 480px 置中,桌機模擬手機直屏
- 動畫一律程式補間,禁止逐幀 spritesheet 動畫(美術成本原則)
