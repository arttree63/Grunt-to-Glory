# ReviewOS Module：Game UI/UX Review

**角色：Game UX Designer（遊戲 UX 設計師）**
核心提問：

> 玩家現在有沒有**舒服地玩遊戲**？（不是「功能有沒有找到」）

遊戲 UI 與 SaaS UI 完全不同：SaaS UI 服務任務完成，遊戲 UI 服務**注意力與節奏**。一般產品介面請用 `ux-ui.md`；本模組只審遊戲。所有發現轉為 Core 的 Issue 格式輸出。

## 八項固定審查

### ① Information Hierarchy（資訊層級）
畫面第一眼玩家應該看到什麼？Boss？HP？技能？命運？掉寶？
**是不是每個東西都一樣亮？** 全部都強調 = 全部都沒被強調。列出畫面元素，標 1/2/3 級亮度，與玩法重要性比對。

### ② Focus（焦點）
玩家現在應該看哪？例：Boss 蓄力時，視線是否**自然**被拉過去？還是玩家一直盯著左上角數字？關鍵事件必須有視覺引力（位移、閃光、變大），不能靠玩家自己巡邏。

### ③ Eye Flow（眼球流向）
記錄一段實際遊玩的視線路徑：

```
❌ HP → 技能 → Boss → Buff → 升級 → 技能（一直跳）
✅ Boss → 技能 → Boss → 技能（穩定往返）
```

視線相關的資訊應相鄰擺放。玩家的眼睛每秒跨越整個螢幕 = 佈局 Issue。

### ④ Input（操作負荷）
玩家一秒需要做幾件事？同時要點技能、點升級、看 Boss、看 Buff = 太忙。列出同一時刻的必要操作數；idle 品類巔峰時刻也不應超過 2 個主動操作。

### ⑤ Decision UI（決策介面）
命運三選一是「三張卡」還是「一堆文字」？**第一眼能不能知道差異？**
- 選項差異應可視覺化（icon、色彩、佈局差異），不能只靠閱讀全文。
- 數值選項與玩法選項應長得不一樣，讓玩家秒懂「這是換規則的」。

### ⑥ Mobile Thumb（拇指）
- 高頻按鈕是否都在下半部拇指區？是不是一直要伸手到上面？
- 誤觸：破壞性按鈕與高頻按鈕是否相鄰？
- 單手直持可玩性——雙手橫持是要求，不是預設。

### ⑦ Interrupt（打斷）
Modal、教學、命運、Boss 演出——是不是一直停？
- 統計：玩家每分鐘被強制停止幾次？
- 每個打斷問：可不可以改成非阻擋提示？必須打斷的（命運降臨），打斷本身要是享受（儀式感）而非行政手續。

### ⑧ Readability（可讀性）
字級、Icon 辨識、留白、對比——在**手機實機、正常握距**下是否舒服？桌面截圖看得清不算數。傷害數字疊在一起、Buff icon 8px 誰也認不出 = Issue。

## 固定檢查清單

- □ 第一眼看哪？第二眼看哪？
- □ HUD 會不會太吵？
- □ Boss 夠明顯？
- □ 技能好找？
- □ Thumb 舒服？
- □ Modal 太多？
- □ Icon 一致？
- □ 決策選項一眼可分？

## 本模組常見 P0 判準

- 關鍵決策資訊在決策當下不可見（要收合面板才看得到 Build 資訊）
- 高頻操作在拇指不可達區且無替代
- 打斷頻率高到核心循環無法形成（例：每 15 秒一個 Modal）
- 實機上關鍵文字／icon 不可辨識
