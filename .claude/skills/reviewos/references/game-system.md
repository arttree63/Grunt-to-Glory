# ReviewOS Module：Game System Review

**角色：Principal Systems Designer（首席系統設計師）**
核心提問：

> 這個系統有存在的理由嗎？刪掉它，遊戲會變差嗎？

只審系統層：存在理由、身分、重疊、組合、最佳解。不評論好不好玩（Experience 的事）、不評論介面（Game UI 的事）。所有發現轉為 Core 的 Issue 格式輸出。

## 三道門（任一不過 = P0，退回設計）

### 門 0：Purpose（存在目的）
這個系統存在的目的？若答案是「提高 DPS」→ 直接打回票，因為所有東西都會變成同一件事。合格答案必須指向一種**體驗**。

### 門 1：System Identity（系統身分）
每個系統只能回答一件事。列出全遊戲身分表確認無重疊：

| 系統 | 身分（範例） |
|---|---|
| 金幣 | 投資本輪 |
| 命運 | 改變規則 |
| 裝備 | 改變 Build |
| 傳承 | 永久成長 |
| Boss | 檢驗 Build |
| 敵人 | 提出問題 |

兩個系統回答一樣 = 重疊 → Issue（打回或合併）。

### 門 2：Cost(玩家成本)
玩家為這個系統付出什麼（注意力、操作、學習）？標記注意力頻率：每輪一次／每分鐘一次／持續佔用。idle/clicker 品類注意力預算極低，持續佔用者需極強理由。

## Distinct Feel（P0 級固定檢查）

**這個新功能是不是只是另一種 DPS？** 列出所有輸出來源（分身、傭兵、燃燒、軍旗、點擊、普攻、技能…），若最後都是「多打一份傷害」→ `[P0] No Distinct Feel`。每個玩法必須改變玩家的**行為或注意力模式**，不只是傷害公式的一項。

## 系統健康檢查清單

- □ 每個系統存在理由？（非 DPS 答案）
- □ 每個資源存在理由？
- □ 功能是否重疊？
- □ 是不是可以刪掉？（刪掉後遊戲沒變差 = 應該刪）
- □ 是不是玩家永遠不用？（存在但無人觸碰 = 死系統）
- □ 是不是只有第一次有趣？（新奇消耗品 vs 可重複深度）
- □ 是不是會形成 Meta？（社群會討論 Build 嗎）
- □ 是不是有最佳解？（有唯一最佳解 = 所有其他選項是假的）
- □ 是不是可以互相組合？（系統 × 系統的乘法空間）
- □ 是不是值得學？（學習投資 vs 回報）

## 最佳解與組合審查

- **最佳解檢測**：對每組選項問「數值上有沒有嚴格優勢解（strictly dominant）？」有 → 該組退化為假選擇，標 P1 以上。
- **組合矩陣**：畫出系統 × 系統交互表。空格太多 = 系統彼此孤立，各自只是平行的進度條。
- **Meta 潛力**：玩家之間有沒有「你走哪路」可聊？聊不起來的 Build 系統只是加點表。

## Economy（經濟子審查）

- 每種貨幣的水龍頭（產出）與水槽（消耗）是否平衡？後期資源是否失去意義（溢出無處花）？
- 付費點是否販賣「跳過無聊」？若是，遊戲本體有無聊段落 → 另開 Issue 指向該段落。
- 兩種貨幣若可互相兌換且用途重疊 = 其實是一種貨幣，違反門 1。

## Progression（成長子審查）

- 成長感來自「能力邊界擴張」還是「數字變大」？每個成長節點是否解鎖新行為？
- 卡關點是「考題」（換 Build 能過）還是「付費牆／時間牆」（只能等）？
