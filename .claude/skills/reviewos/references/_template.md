# ReviewOS Module Template：如何新增模組

新模組 = 在 `references/` 新增一個 `.md`，並在 SKILL.md 的模組路由表加一列。模組**繼承 Core**：不重複哲學、Priority、Issue 格式、Workflow——只寫該領域的專業判準。

## 模組檔案結構（照抄此骨架）

```markdown
# ReviewOS Module：<名稱>

涵蓋：<子領域清單>
核心提問：

> <一句話：這個領域的資深專家審查時，心裡問的那個問題>

所有發現轉為 Core 的 Issue 格式輸出。

## 審查前先建立脈絡
<2-4 個必答問題——這個領域的「產品目標」如何具體化>

## <判準區塊 × N>
<每個子領域一節。判準必須：可觀察、可驗證、附正反例>

## 本模組常見 P0 判準
<3-5 條：什麼情況在此領域構成 Critical>
```

## 寫判準的品質標準

1. **判準是「問題」不是「教條」**：❌「應遵守 SOLID」✅「六個月後接手的人會在哪裡受苦？」
2. **每條判準可產生 Issue**：讀完判準，審查者知道去看什麼、看到什麼算違反。
3. **附失敗徵兆**：好判準像 game 模組的三欄標記法——預期／觸發條件／失敗徵兆。
4. **正反例**：❌ 寫法 vs ✅ 寫法，一組勝過三段解釋。
5. **控制長度**：單一模組 100-200 行。超過代表該拆成兩個模組。

## 新增流程

1. 用上述骨架寫 `references/<module>.md`
2. 在 `SKILL.md` 模組路由表加一列（審查對象關鍵字 → 檔案）
3. 若觸發詞不在 SKILL.md description 中，補上
4. 用一個真實案例跑一次審查，確認判準能實際產出 Issue；產不出來的判準刪掉

## 規劃中的模組（依需要建立）

- Narrative Review 獨立模組（若敘事比重提高）
- Pricing Review（定價策略——Gbtree/Arttree 適用）
- Plugin/Extension Review（WordPress 外掛上架審查標準）
