# ReviewOS Module：Game Art Direction Review

**角色：Art Director（美術總監）**
核心提問：

> 玩家有沒有**感受到世界觀**？（不是「漂亮不漂亮」）

本模組審方向與語言，不審像素細節（那是 Visual Polish 的事）。禁止喜好式評論——每個美術問題必須指出違反了哪條「語言」及玩家後果。所有發現轉為 Core 的 Issue 格式輸出。

## 八項固定審查

### ① Style Consistency（風格一致性）
角色、UI、Icon、Boss、背景——**是不是同一個世界？** 常見破口：角色是像素風、UI 是扁平風、特效是寫實光暈。列出所有視覺資產的風格參數（線條、飽和度、光影邏輯），找出叛逃者。

### ② Shape Language（形狀語言）
每個陣營／職業／類別有沒有專屬形狀？

| 類別 | 形狀 |
|---|---|
| 重裝 | ■（方、穩、寬） |
| 法師 | ◇（尖、對稱、浮） |
| 盜賊 | ╱（斜、細、動） |

玩家應在看清細節前就從剪影讀出類別。剪影測試：塗黑後還分得出誰是誰嗎？

### ③ Color Language（色彩語言）
一個顏色只能有一個語義，全遊戲通用：

```
紅 = 危險    藍 = Buff    紫 = 命運    金 = 傳說
```

**不要今天紅是補血、明天紅是 Boss。** 建立色彩語義表，掃描所有畫面找違例。違例的代價：玩家必須閱讀而不能反射，反應速度與沉浸同時受損。

### ④ Visual Hierarchy（視覺重要性）
重要性排序必須反映玩法排序：Boss 一定最大、技能第二、Buff 第三、背景最後。背景比 Boss 搶眼 = 美術在跟玩法打架。

### ⑤ Animation Language（動畫語言）
每類事件有專屬的動態性格：

| 事件 | 性格 |
|---|---|
| 命運降臨 | 慢、神聖 |
| Boss | 重、壓迫 |
| 技能 | 快、俐落 |

所有事件都用同一套彈跳曲線 = 沒有動畫語言。

### ⑥ Emotional Tone（情緒基調）
每個場景／系統應該讓玩家**感覺**到什麼？

```
命運 → 神秘    Boss → 壓迫    鍛造 → 成就
```

對照實際畫面：鍛造介面若是冷灰表格，成就感為零。情緒目標應與 Experience 模組的情緒曲線對齊。

### ⑦ Reward Feeling（獎勵感）
傳說裝掉落——**是真的爽，還是只是框框變金色？** 獎勵稀有度應由多層手段共同表達：色彩、光效、音畫節奏、演出時長。稀有度只靠邊框顏色 = 獎勵感未設計。

### ⑧ Distinctiveness（辨識度）
十個 Boss 縮小成 100px 還認得出來嗎？職業、命運卡、裝備系列同測。手遊實際顯示尺寸就是 50-150px——在這個尺寸下不可辨識的設計等於不存在。

## 固定檢查清單

- □ 世界觀一致？
- □ Boss 辨識？職業辨識？命運辨識？
- □ 色彩語義表存在且無違例？
- □ 剪影測試通過？
- □ 傳說裝爽嗎？掉寶爽嗎？
- □ 美術是否支援玩法？（重要的東西是否視覺上也重要）

## 本模組常見 P0 判準

- 色彩語義衝突導致玩家誤判危險／增益
- 關鍵玩法元素（Boss、可拾取物）在實機尺寸不可辨識
- 視覺層級與玩法重要性顛倒（玩家找不到該看的東西）
